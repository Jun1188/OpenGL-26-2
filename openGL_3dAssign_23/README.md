# 실습23: 로봇

lecture_pdf/homework의 실습23 PDF 기준. GridLayout → addWalkingRig → CharacterBody/stepCharacter → poseWalkingRig로 연결한다. 다른 색 팔·다리, 머리·코·몸통, 랜덤 배치 장애물3개, 가장자리/장애물 방향반전, 속도별 보행진폭, 점프·윗면착지를 제공한다. 실행 시 random_device 시드를 한 번 사용하고 I 리셋에서도 엔진을 유지해 새 위치를 뽑는다. 시드는 콘솔에 표시한다.

W/A/S/D는 +Z/-X/-Z/+X로 진행 방향을 설정하고 계속 걷는다. +/- 속도(0~3), J 점프, Space 보행 정지/재개. 정지 후 J는 제자리 점프, 보행 중 J는 수평 이동을 유지해 장애물에 올라간다. O: 시선(target-position)과 바깥 법선의 양의 내적이 최대인 맞은편 내부 벽을 선택하여 벽 중심 기준 가로·세로 균등 축소. 진행률 1에서 벽을 숨기고, 복원 시 배율 1로 되돌린다. 다시 O를 누르면 카메라를 옮겼어도 같은 벽을 원상복귀한다. 복원이 끝난 뒤 다음 벽 선택이 가능하다. I 리셋, x/X·z/Z 카메라 이동, y/Y 카메라 target 기준 Y공전, Q/Esc 종료.

초기화는 네 옆벽을 모두 만들고 크기·가시성을 복원한다. 초기 시점에서는 -Z 벽(face1)을 O 대상으로 고른다. 벽 윤곽선은 그리지 않는다. GL_LINES는 면 컬링으로 제거되지 않으므로 윤곽선을 요청하면 컬링된 벽에도 선이 남는다. Front cull은 시점에 따라 앞면을 제거하는 표시 정책이며, O로 완전히 열린 벽의 숨김 상태와 별개다. 이전의 벽별 독립 토글은 다른 벽을 선택한 뒤에도 이전 벽을 열린 채 남길 수 있었으므로 단일 activeWall로 교체했다. 이 원인과 수정은 소스 기준이며 실제 카메라 공전 화면 확인은 사용자에게 맡긴다.

stage의 각 면에 다른색/Front컬링을 적용한다. 장애물·로봇은 일반 물체다. 충돌은 축 정렬 대리 상자이며 팔다리 개별 충돌과 정밀 강체가 아니다. .sln에서 Debug/Release x64를 사용한다. 빌드·실행·테스트는 하지 않았고 사용자에게 맡긴다.
