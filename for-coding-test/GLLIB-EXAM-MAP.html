gllib.cpp 실습 지도

바닥과 기준 직육면체에서 시작합니다. 시험 문제가 정해지면 장면과 키를 추가하고 필요한 배치·변환 패턴을 호출하세요.

기본 장면과 시험용 공통 함수

처음 받은 문제에 맞춰 장면, 입력, 상태를 결정하는 시작 코드입니다.

장면과 대상
이전받침·기둥·막대를 부모와 자식으로 연결하고 막대를 직접 제어했습니다.
현재바닥과 기준 직육면체를 하나씩 등록합니다. 치수와 배치는 examLayout에 있습니다. 필요한 객체 ID는 문제를 풀면서 Console에 저장합니다.
키 입력
이전방향키 분기 또는 KeyState로 키 상태를 기록했습니다.
현재onKey()의 GLFW_PRESS 분기에 단발 동작을 모읍니다. 누르는 동안 움직이는 문제가 나오면 해당 키의 상태만 추가합니다.
회전 갱신
이전저울 막대나 기본 기둥이 방향키로 회전했습니다.
현재기본 장면은 정지 상태로 시작합니다. 회전이 필요하면 EXAM_RUN에서 프레임 콜백을 연결하고 advanceSpin()을 사용합니다.
클릭과 드래그
이전마우스 로그가 runExam() 안에 있었고 화면 광선은 pickAt() 내부에서 사용했습니다.
현재onMouse()가 선택 로그를 담당합니다. screenRayAt()의 광선을 삼각형 피킹과 intersectRayPlane()에서 함께 쓸 수 있습니다.
장면 다시 시작
이전장면 생성부는 주로 도형과 카메라를 구성했습니다.
현재initScene()은 색상 복원 기록을 초기화합니다. 장면을 재구성할 때는 먼저 scene.clear()를 호출하고, 문제별 ID·타이머·키 상태도 초기값으로 돌립니다.
프레임워크 정리
자동 UV 투영을 제거했습니다. 기존 UV에 배율·회전·이동을 적용하는 함수도 제거했습니다. 이미지 디코딩·GPU 텍스처 경로를 제거했고 OBJ의 UV와 setTexcoords()는 유지했습니다.
직선 모션은 경로 모션의 시간 검사를 사용합니다. 자동 재생은 사용자 onUpdate(dt) 다음에 진행합니다. Application::run()은 한 곳에서 자원을 정리한 뒤 반환하거나 예외를 다시 던집니다.
구·원뿔·사면체 생성과 진단 단계명·진입 추적을 덜어냈습니다. 육면체와 실습 26의 사각뿔은 유지합니다. 모션은 변환 단계와 레이어를 재생하고, 시험 상태 변경은 onUpdate(dt)에 작성합니다.

시험에서 바꿀 곳

장면을 만든 뒤 필요한 객체의 ID를 저장하고, 먼저 단발 키를 추가합니다. 문제에 시간에 따른 동작이 있으면 프레임 갱신을 연결합니다.

    C는 면 색상 변경, Shift+C는 복원입니다. 문제의 C 키 요구는 onKey()에서 연결합니다.

    PDF와 함께 볼 때

    PDF의 줄 번호는 작성 당시 기준입니다. 현재 소스에서는 같은 함수 이름이나 EXAM_ 검색어로 이동하세요.

    • 첫 실행 확인은 창과 기본 장면을 띄운 뒤 Q 또는 Esc로 닫는 절차입니다. PDF의 시작 화면은 바닥과 큐브이며, 현재 소스는 바닥과 기준 직육면체를 띄웁니다. 인쇄 요약 1–3쪽
    • 입력에서 상태를 저장하고 onUpdate(dt)에서 기존 ID의 변환을 갱신하는 순서는 같습니다. PDF 완성 예제의 WASD 이동·관성·리셋을 적용할 때는 wHeld_ 같은 개별 플래그를 추가하고, EXAM_RUN에서 갱신과 포커스 콜백을 연결합니다. 콜백 API 가이드 4–9쪽
    • PDF의 받침·크레인·차량은 객체 생성과 피벗을 연습하는 별도 장면입니다. 바닥 위에 놓는 중심 계산과 부모 기준 배치, 자전·공전 규칙은 현재도 그대로 적용합니다. 콜백 API 가이드 2–3쪽 · 10–12쪽 · 인쇄 요약 5쪽
    • OBJ는 현재 소스의 EXAM_PRIMITIVES에서 파일 경로와 직접 등록 예시를 찾을 수 있습니다. PDF의 previewObjTemplates_ 키 예제는 현재 시작 장면에서 loadObj()와 Scene 직접 등록으로 적용합니다. 외부 GLSL을 쓰는 문제는 EXAM_RUN에서 config.shaderDirectory를 지정합니다. 인쇄 요약 4쪽
    누르는 동안 움직이는 입력과 방향을 기억하는 입력

    누르는 동안만 움직이는 문제는 PDF처럼 필요한 키의 플래그를 Console에 추가합니다. onKey()의 GLFW_PRESS 필터 앞에서 눌림과 해제를 기록하고, onFocus(false)에서도 해제합니다. 한 번 눌러 계속 돌리는 문제는 방향 값 하나를 저장합니다.

    PDF 5·8쪽의 입력 방향

    glm::vec3 direction{
    float(dHeld_) - float(aHeld_),
    0.0f,
    float(wHeld_) - float(sHeld_)
};

    계속 회전하는 문제의 방향 값

    // onKey()의 GLFW_PRESS 구간
if (key == GLFW_KEY_LEFT || key == GLFW_KEY_RIGHT) {
    const int direction = key == GLFW_KEY_LEFT ? -1 : 1;
    direction_ = direction_ == direction ? 0 : direction;
}

    두 예제 모두 EXAM_RUN에서 onUpdate(dt)를 연결합니다. 방향을 기억하는 예는 같은 방향키를 다시 누르면 정지하고, 반대 키를 누르면 반대로 돕니다. advanceSpin()에 direction_ × 초당 각속도를 넘깁니다. 콜백 API 가이드 5·7–8쪽

    main에서 화면 교체까지

    화살표는 진행 순서입니다. 함수 상자를 선택하면 호출 조건과 소스 줄이 나옵니다.

    Application::run() 상세 실행 경로
    1. 6013–6039행 · 실행 준비

      진단을 설정하고 재귀 실행이나 다른 Application과의 동시 실행을 거부합니다. 콘솔 코드 페이지와 실행 플래그를 설정합니다.

    2. 5834행, 6045–6056행 · 초기화

      initialize()가 GLFW 오류 콜백과 OpenGL 3.3 코어 창을 준비합니다. 컨텍스트를 연결한 다음 GL 함수 로더, VSync, 셰이더, 렌더러와 자산 로더를 설정하고 GLFW 이벤트를 등록합니다. 성공하면 등록된 initScene()을 한 번 부릅니다. 둘 중 하나가 실패하면 -1로 종료합니다.

    3. 1631행, 6057–6080행 · 이벤트와 대기

      glfwPollEvents() 후 콜백 예외와 닫힘 요청을 확인합니다. GLFW 이벤트 콜백에서 예외가 발생하면 dispatch()가 예외를 보관하고 닫힘을 요청합니다. 프레임버퍼 폭이나 높이가 0이면 glfwWaitEvents()로 기다린 뒤 시간을 다시 기록하고 해당 반복을 건너뜁니다.

    4. 6082–6099행 · 시간과 장면 갱신

      dt를 0~0.05초로 제한해 등록된 onUpdate(dt)를 실행합니다. 다시 닫힘 요청을 확인한 다음 Scene의 모션 시간을 갱신합니다. 모션 갱신이 실패하면 -1로 루프를 끝냅니다.

    5. 5793행, 6101–6123행 · 렌더와 화면 교체

      ensureContext()로 렌더 스레드와 현재 GL 컨텍스트를 확인하고 필요하면 다시 연결합니다. 렌더 콜백이 있으면 실행하고, 기본 경로는 renderScene()입니다. 성공한 프레임은 glfwSwapBuffers()로 표시합니다. 컨텍스트, 렌더, 화면 교체 중 오류가 발생하면 -1로 종료합니다.

    6. 5949행, 6126–6144행 · 정리와 반환

      shutdown()은 자산 로더를 정리하고, GL 컨텍스트가 유효하면 GPU 객체를 삭제합니다. 컨텍스트가 실패했다면 GL 삭제 호출을 건너뛰고 렌더러 핸들을 초기화합니다. 창을 파괴하고 GLFW를 종료한 뒤 실행 플래그를 비웁니다. 일반 종료는 코드 값을 반환하며, 예외 경로는 정리 후 예외를 다시 던집니다.

    C++ 소유권과 장면의 부모 관계

    소유 관계는 객체의 수명을, 장면의 부모 관계는 좌표 변환을 결정합니다.

    Scene의 생성부터 렌더와 피킹까지
    1. 4080행 · 생성

      크기를 받아 육면체의 면을 만들고 초기 위치를 Transform3D::basis에 저장합니다.

    2. 4044행 · 등록

      형상과 변환을 확인하고 Scene에 저장합니다. 돌려준 ID를 나중에 키 입력, 피킹, 변환에 사용합니다. 등록 시 형상 버전도 갱신합니다.

    3. 4234행 · 계층

      자식 ID를 부모 ID에 연결합니다. worldMatrix()는 부모의 월드 행렬에 자식 변환을 합성합니다. 연결할 때 기존 월드 자세를 유지하려면 setParentPreserveWorld()를 사용합니다.

    4. 4460행 · 변환

      이동이나 회전은 등록한 ID의 자세를 갱신합니다. 정점 자체를 교체하는 경우 렌더러가 형상 버전을 확인해 GPU 버퍼를 다시 준비합니다.

    5. 4378행 · 렌더와 피킹

      두 경로에서 같은 면의 월드 행렬을 사용합니다. 렌더는 카메라 행렬을 곱해 화면에 그리고, 피킹은 월드 광선과 면의 삼각형을 비교합니다.

    6. 4590행 · 재구성

      장면과 모션 연결을 비운 뒤 도형을 다시 등록하고 새 ID를 저장합니다.
