OpenGL 시험 실전 튜토리얼

새 x64 프로젝트에서 바닥과 큐브를 먼저 띄운다. 그다음 접이식 검사판으로 장면 등록, 키 입력, 경첩 회전까지 연결한다. 낯선 문제도 같은 순서로 시작하되 문제에서 요구한 물체·좌표계·상태를 다시 정한다. 조명 편집과 GLSL 직접 작성은 필수 요구에서 벗어나면 선택 학습으로 둔다.

이 자료는 시험 전 연습용이다. 반입 항목은 gllib.cpp, lecture_pdf, obj이며 합계 10,928,177바이트(약 10.93 MB)다. 현장에는 인터넷이 없으므로 헤더·LIB·DLL과 C++ 개발 도구를 현장에서 제공하는지 미리 확인한다. 시험장 PC의 설치 상태는 확인되지 않았다. gllib.cpp · 이 PC에서 수행한 검증

1. 준비 PC에서 의존성 확보

이미 파일이 있으면 기존 배포본 사용

이 PC에서 검증할 때는 OpenGL-26-2의 normal/dependencies에 있는 GLEW 2.3.1, GLFW 3.4 Win64, GLM 1.0.3을 연결했다. GLEW는 헤더를 사용하며 필요한 함수 로더는 gllib.cpp에 들어 있다. GLFW는 헤더, x64 가져오기 라이브러리 glfw3dll.lib, 그와 같은 배포본의 glfw3.dll이 필요하다. GLM은 연관 헤더를 포함한 전체 glm 디렉터리가 필요하다. 이 PC에서 연결한 SDK 폴더

의존성 실제 경로의 마지막 부분 사용 단계
GLEW glew-2.3.1/include/GL/glew.h 컴파일. 추가 포함 경로는 include까지.
GLFW 헤더 glfw-3.4.bin.WIN64/include/GLFW/glfw3.h 컴파일. 추가 포함 경로는 include까지.
GLM glm/glm/glm.hpp 컴파일. glm/glm.hpp를 찾을 수 있는 바깥 glm 폴더 지정.
GLFW LIB glfw-3.4.bin.WIN64/lib-vc2022/glfw3dll.lib 링크. 추가 라이브러리 경로는 lib-vc2022까지.
GLFW DLL glfw-3.4.bin.WIN64/lib-vc2022/glfw3.dll 또는 배포본의 dll/glfw3.dll 실행. EXE 폴더에 배치.

개인 PC에 C++ 도구가 없으면 Visual Studio Installer에서 C++를 사용한 데스크톱 개발 워크로드와 MSVC x64 도구, Windows SDK를 설치한다. 현장에서는 제공된 Visual Studio와 설치된 도구 집합을 사용한다. Microsoft C++ 설치 문서

파일도 없으면 PowerShell로 준비

gllib.cpp의 EXAM_INSTALL (18행)에 아래 PowerShell 명령이 있다. Windows 기본 PowerShell 5.1과 PowerShell 7을 모두 지원한다. Visual Studio 솔루션 탐색기에서 프로젝트를 우클릭해 터미널에서 열기를 누른 뒤(gllib.cpp가 있는 폴더) 붙여 넣는다. 프로젝트 옆 dependencies\에 자동 배치하므로 Visual Studio의 추가 포함/라이브러리 디렉터리를 수동 입력할 필요가 없고, x64\Debug와 x64\Release에 glfw3.dll까지 복사한다. 기준 파일이 하나라도 없으면 ZIP 세 개를 다시 받는다. 인터넷이 열려 있을 때 설치와 첫 실행을 끝낸다. GLEW 배포 파일 · GLFW 배포 파일 · GLM 배포 파일

& {
    $ErrorActionPreference = 'Stop'
    $ProgressPreference = 'SilentlyContinue'
    [Net.ServicePointManager]::SecurityProtocol = [Net.SecurityProtocolType]::Tls12
    if (!(Test-Path -LiteralPath 'gllib.cpp' -PathType Leaf)) {
        throw 'gllib.cpp가 있는 프로젝트 폴더에서 실행하세요. (VS: 프로젝트 우클릭 -> 터미널에서 열기)'
    }

    $req = @(
        'dependencies\glew-2.3.1\include\GL\glew.h',
        'dependencies\glfw-3.4.bin.WIN64\include\GLFW\glfw3.h',
        'dependencies\glfw-3.4.bin.WIN64\lib-vc2022\glfw3dll.lib',
        'dependencies\glm\glm\glm.hpp',
        'dependencies\dll\glfw3.dll'
    )
    if (@($req | Where-Object { !(Test-Path -LiteralPath $_ -PathType Leaf) }).Count -gt 0) {
        $null = New-Item -ItemType Directory -Force -Path 'dependencies\dll'
        $tmp = Join-Path $env:TEMP ('gl_deps_' + [guid]::NewGuid().ToString('N'))
        $null = New-Item -ItemType Directory -Force -Path $tmp
        try {
            $packages = [ordered]@{
                'glew' = 'https://github.com/nigels-com/glew/releases/download/glew-2.3.1/glew-2.3.1-win32.zip'
                'glfw' = 'https://github.com/glfw/glfw/releases/download/3.4/glfw-3.4.bin.WIN64.zip'
                'glm'  = 'https://github.com/g-truc/glm/releases/download/1.0.3/glm-1.0.3.zip'
            }
            foreach ($name in $packages.Keys) {
                $zip = Join-Path $tmp "$name.zip"
                Invoke-WebRequest -UseBasicParsing -Uri $packages[$name] -OutFile $zip
                if ($name -eq 'glm') {
                    $stage = Join-Path $tmp 'glm'
                    Expand-Archive -LiteralPath $zip -DestinationPath $stage -Force
                    $glmHpp = Get-ChildItem -LiteralPath $stage -Recurse -File -Filter 'glm.hpp' |
                        Where-Object { $_.Directory.Name -eq 'glm' } | Select-Object -First 1
                    if (!$glmHpp) { throw 'GLM 압축에서 glm/glm.hpp를 찾지 못했습니다.' }
                    if (Test-Path -LiteralPath 'dependencies\glm') { Remove-Item -LiteralPath 'dependencies\glm' -Recurse -Force }
                    $null = New-Item -ItemType Directory -Force -Path 'dependencies\glm'
                    Copy-Item -LiteralPath $glmHpp.Directory.FullName -Destination 'dependencies\glm\glm' -Recurse -Force
                } else {
                    Expand-Archive -LiteralPath $zip -DestinationPath 'dependencies' -Force
                }
            }
            Copy-Item -LiteralPath 'dependencies\glfw-3.4.bin.WIN64\lib-vc2022\glfw3.dll' -Destination 'dependencies\dll\glfw3.dll' -Force
        } finally {
            if (Test-Path -LiteralPath $tmp) { Remove-Item -LiteralPath $tmp -Recurse -Force }
        }
    }

    foreach ($outDir in 'x64\Debug', 'x64\Release') {
        $null = New-Item -ItemType Directory -Force -Path $outDir
        Copy-Item -LiteralPath 'dependencies\dll\glfw3.dll' -Destination (Join-Path $outDir 'glfw3.dll') -Force
    }
    Write-Host '[완료] dependencies\ 설치 및 x64\Debug, x64\Release에 glfw3.dll 복사 완료.'
    Write-Host '출력 폴더가 다른 경우: Copy-Item dependencies\dll\glfw3.dll <EXE폴더>\ -Force'
}

dependencies\가 프로젝트 폴더에 배치되면 gllib.cpp 178·194·206행의 __has_include와 #pragma comment(lib, ...)가 헤더와 glfw3dll.lib를 자동 연결한다. 프로젝트 출력 폴더가 x64\Debug나 x64\Release가 아닌 경우에만 dependencies\dll\glfw3.dll을 실제 EXE 폴더에 복사한다. 인터넷이 차단된 현장 PC에서는 아래 EXAM_OFFLINE으로 주최 측 제공 경로를 조회한다.

2. 새 프로젝트에서 첫 화면 띄우기

주석 맞춤법 표시는 편집 → 고급 → 맞춤법 검사 전환에서 끌 수 있다. gllib.cpp 상단 안내를 참고한다.

  1. Visual Studio에서 빈 C++ 프로젝트 또는 C++ 콘솔 앱을 만든다. 솔루션 플랫폼을 x64로 바꾼다.
  2. 프로젝트 폴더에 gllib.cpp와 obj를 둔다. 소스 파일 → 추가 → 기존 항목에서 gllib.cpp를 추가한다. 콘솔 앱이 만든 main()의 .cpp는 빌드에서 제외한다.
  3. 솔루션 탐색기에서 프로젝트를 우클릭해 속성을 연다. 구성을 모두, 플랫폼을 x64로 두고 아래 값을 맞춘다. 제공된 설정이 있는 항목은 경로를 확인하고 상속 값을 유지한다.
  4. 빌드 → 솔루션 빌드를 누른다. 출력에서 이번에 생성된 EXE 경로를 확인하고, 같은 배포본의 glfw3.dll을 그 폴더에 둔다.
  5. Ctrl+F5로 실행한다. 바닥과 큐브가 보이면 Q 또는 Esc로 닫는다. 이 시점에는 OBJ나 별도 GLSL의 성공 여부와 관계없이 기본 도형이 떠야 한다.
프로젝트 속성 설정
C/C++ → 언어 → C++ 언어 표준 ISO C++17 이상
C/C++ → 명령줄 → 추가 옵션 /utf-8 권장
C/C++ → 미리 컴파일된 헤더 gllib.cpp에 사용 안 함
C/C++ → 일반 → 추가 포함 디렉터리 EXAM_INSTALL로 프로젝트 옆 dependencies\에 배치했으면 생략 가능. 현장 SDK 사용 시 GL/glew.h, GLFW/glfw3.h, glm/glm.hpp의 상위 경로 세 개 지정
링커 → 일반 → 추가 라이브러리 디렉터리 dependencies\ 배치 시 자동 링크. 현장 SDK 사용 시 x64 glfw3dll.lib 폴더 지정 (gllib.cpp 196행 pragma)
링커 → 시스템 → 하위 시스템 콘솔. 빈 프로젝트에서 지정이 필요할 때 선택한다.

Visual Studio의 프로젝트 폴더와 실행 파일 폴더를 구분한다. 현장이 이미 GLFW DLL 검색 경로를 제공하면 그 설정을 쓴다. 직접 복사할 때는 Debug와 Release의 실제 출력 폴더를 각각 본다. GLEW는 헤더가 필요하며 glew32.lib와 glew32.dll은 내장 로더 구성에 필요하지 않다.

현장 제공 SDK 경로를 PowerShell로 확인

시험장에서는 네트워크 연결이 필요 없는 이 명령으로 제공 SDK 디렉터리를 조회할 수 있다. gllib.cpp의 EXAM_OFFLINE (7629행)에도 같은 코드가 있다. 출력된 세 포함 경로를 붙여 넣고 x64 MSVC용 LIB를 고른다. 현장에 glfw3dll.lib 대신 정적 glfw3.lib만 있으면 안내 메시지에 따라 gllib.cpp 192행·196행을 전환한다.

& {
    $ErrorActionPreference = 'Stop'
    $sdkRoot = Read-Host '시험장에 제공된 SDK 폴더 경로'
    if (!(Test-Path -LiteralPath $sdkRoot -PathType Container)) {
        throw "SDK 폴더를 찾지 못했습니다. 제공 경로를 확인하세요. $sdkRoot"
    }

    $includeDirs = foreach ($name in 'GL/glew.h', 'GLFW/glfw3.h', 'glm/glm.hpp') {
        $suffix = '\' + $name.Replace('/', '\')
        $header = Get-ChildItem -LiteralPath $sdkRoot -Recurse -File -Filter (Split-Path $name -Leaf) |
            Where-Object { $_.FullName.EndsWith($suffix, [StringComparison]::OrdinalIgnoreCase) } |
            Select-Object -First 1
        if (!$header) { throw "필수 헤더를 찾지 못했습니다. $name" }
        $header.Directory.Parent.FullName
    }
    "IncludeDirectories = " + ($includeDirs -join ';')

    $dllLibs = @(Get-ChildItem -LiteralPath $sdkRoot -Recurse -File -Filter 'glfw3dll.lib')
    $staticLibs = @(Get-ChildItem -LiteralPath $sdkRoot -Recurse -File -Filter 'glfw3.lib')
    $dlls = @(Get-ChildItem -LiteralPath $sdkRoot -Recurse -File -Filter 'glfw3.dll')
    if ($dllLibs.Count) {
        foreach ($lib in $dllLibs) {
            "LibraryDirectory (DLL용) = " + $lib.DirectoryName
            $dll = Join-Path $lib.DirectoryName 'glfw3.dll'
            if (Test-Path -LiteralPath $dll -PathType Leaf) { "  RuntimeDll = $dll" }
        }
    } elseif ($staticLibs.Count) {
        Write-Host '[주의] glfw3dll.lib 대신 정적 glfw3.lib만 발견되었습니다.'
        foreach ($lib in $staticLibs) { "LibraryDirectory (정적) = " + $lib.DirectoryName }
        Write-Host '-> gllib.cpp 192행 #define GLFW_DLL을 주석 처리하고 196행 glfw3dll.lib를 glfw3.lib로 바꾸세요.'
    } else {
        throw 'glfw3dll.lib 또는 glfw3.lib를 찾지 못했습니다. 현장에서 제공한 x64 배포본을 확인하세요.'
    }
    if ($dlls.Count) {
        '제공된 DLL 후보:'
        $dlls | ForEach-Object { $_.FullName }
    }
}

4. 실습 A · 접이식 검사판을 끝까지 구현

요구 · 바닥 위에 판 하나를 둔다. Space를 누르면 윗변 경첩을 기준으로 0°에서 −90°까지 열린다. 중간에 다시 누르면 그 각도에서 돌아온다. R로 닫힌 상태를 복구하고 Q·Esc로 종료한다.

  • 판의 높이 1.2, 중심 기준 위쪽 끝 y=0.6.
  • 월드 경첩 위치 (0, 1.65, 0). 닫힌 판의 아래쪽 끝 y=0.45.
  • 열림 목표 −90°, 속도 120°/s. 완전히 열렸을 때 아래쪽 끝 y=1.65, z=1.2.
  • gllib.cpp 사본에서 previewObjTemplates_를 false로 둔다. 아래는 상단 04~07의 예제다.

A1. class Console에 상태 저장

public: 앞에 넣는다. 판의 ID로 매 프레임 같은 도형을 움직인다. panelOpen_은 목표, panelAngle_은 현재 각도다.

std::optional<graphics::EntityId> panel_;
float panelAngle_ = 0.0f;

A2. EXAM_START에 장면 등록

initScene에서 카메라·기본 조명 설정까지 유지한다. 함수 끝의 auto& scene부터 기존 return까지 교체한다. 첫 프레임 전에 onUpdate(0)으로 닫힌 위치를 적용한다.

auto& scene = app_.getScene();
const auto floor = scene.addCuboid({10.0f, 0.2f, 10.0f}, {0.0f, -0.1f, 0.0f});
panel_ = scene.addCuboid({1.6f, 1.2f, 0.08f}, {0.0f, 0.0f, 0.0f});
if (!floor || !panel_)
    return false;
onUpdate(0.0f);
return scene.setTint(*floor, {0.45f, 0.45f, 0.45f}) &&
       scene.setTint(*panel_, {0.35f, 0.7f, 0.95f});

A3. EXAM_INPUT에서 목표만 바꾸기

onKey의 GLFW_PRESS 필터 뒤, Q·Esc 처리 앞에 추가한다. Space를 길게 눌러 발생하는 GLFW_REPEAT는 필터에서 걸러진다.

if (key == GLFW_KEY_SPACE)
    panelOpen_ = !panelOpen_;
if (key == GLFW_KEY_R) {
    panelOpen_ = false;
    panelAngle_ = 0.0f;
}

A4. EXAM_UPDATE에서 경첩 회전

onUpdate의 기존 본문을 교체한다. T(basis) × R × S × T(−localBasis)에서 로컬 경첩이 먼저 원점으로 옮겨진다. 회전 결과를 경첩의 최종 위치에 배치하므로 판이 움직여도 경첩은 고정된다. GLM의 glm::rotate에는 라디안을 전달한다.

if (!panel_)
    return;
const float target = panelOpen_ ? -90.0f : 0.0f;
const float step = 120.0f * dt;
panelAngle_ += std::clamp(target - panelAngle_, -step, step);
graphics::Transform3D t;
t.basis = {0.0f, 1.65f, 0.0f};
t.localBasis = {0.0f, 0.6f, 0.0f};
t.rotation = glm::mat3(glm::rotate(glm::mat4(1.0f), glm::radians(panelAngle_),
                                 glm::vec3(1.0f, 0.0f, 0.0f)));
app_.getScene().setTransform(*panel_, t);

직접 확인할 순서 · 시작 시 수직 → Space로 수평 → 연속 이동 중 Space로 방향 반전 → R로 수직 → Q 또는 Esc. 판 중앙이 돌아가면 localBasis가 비었거나 중심에 놓인 상태다. 경첩 자체가 월드에서 움직이면 basis 또는 부모 프레임을 본다.

예측 연습 · 같은 판을 가운데서 돌리면?

localBasis의 y를 0으로 바꾸면 판의 중심점이 basis에 고정된다. 윗변이 월드에 붙어 있어야 한다는 조건을 어기므로, 중심 회전을 원하는 문제에서만 그 값을 사용한다.

8. 선택 학습 · GLSL과 기본 광원

내장 GLSL에서 한 부분만 바꾸기

gllib.cpp의 5659행 vertexShader와 5679행 fragmentShader는 C++의 R"GLSL(…)GLSL" 문자열이다. shaderDirectory를 비워 두면 이 쌍이 사용된다. 정점 입력은 location 0 위치, 1 색, 2 UV, 3 법선이다. C++ 렌더러가 매 드로우의 P × V × M을 uMVP에 넣는다. 정점 셰이더에서 해당 uniform을 실제로 사용하고, 버텍스 out과 프래그먼트 in의 이름·타입을 맞춘다.

처음 편집할 때는 내장 프래그먼트 셰이더의 마지막 RGB에 0.8을 곱해 원래 변환은 유지되고 색만 어두워지는지 볼 수 있다.

외부 GLSL 파일을 요구할 때

아래 두 파일은 gllib.cpp의 EXAM_GLSL 주석에 있는 색·변환 확인 예제다. 모델 변환은 uMVP와 연결된다. 조명 계산은 이 단순한 셰이더 쌍에 포함되지 않는다.

VertexShader.glsl

#version 330 core
layout(location = 0) in vec3 vPos;
layout(location = 1) in vec3 vColor;
uniform mat4 uMVP;
out vec3 vertexColor;
void main() {
    gl_Position = uMVP * vec4(vPos, 1.0);
    vertexColor = vColor;
}

FragmentShader.glsl

#version 330 core
in vec3 vertexColor;
uniform vec3 uTint;
out vec4 FragColor;
void main() {
    FragColor = vec4(vertexColor * uTint, 1.0);
}
  1. 프로젝트 폴더(gllib.cpp 옆)에 shaders 폴더를 만들어 위 두 파일을 저장한다. 파일 확장자가 .glsl.txt가 되지 않게 확인한다. 파일은 C++ 소스 항목에 추가할 필요가 없다.
  2. EXAM_RUN에서 app.run(config) 전에 config.shaderDirectory = "shaders";를 넣는다. obj/와 동일하게 EXE 폴더 → 현재 작업 폴더 → gllib.cpp 폴더($(ProjectDir)) → 상위 2단계 순으로 자동 탐색하므로 프로젝트 폴더에 두면 복사 없이 동작한다.
  3. 초기 화면을 확인한다. 파일 열기 오류는 경로·이름을, GLSL 컴파일 오류는 파일의 #version과 줄 번호를, 셰이더 링크 오류는 out/in을 확인한다. Required MVP 오류면 uMVP의 이름과 gl_Position에서의 사용을 확인한다.

실행 파일을 단독 폴더로 옮겨 실행해야 하는 경우에만 프로젝트 속성 → 빌드 이벤트 → 빌드 후 이벤트의 명령줄에 아래를 넣어 EXE 옆으로 복사한다.

if not exist "$(TargetDir)shaders" mkdir "$(TargetDir)shaders"
copy /Y "$(ProjectDir)shaders\VertexShader.glsl" "$(TargetDir)shaders\VertexShader.glsl"
copy /Y "$(ProjectDir)shaders\FragmentShader.glsl" "$(TargetDir)shaders\FragmentShader.glsl"

C++에서 밝기를 제어하려면 프래그먼트 GLSL에 uniform float uBrightness;를 선언하고 vertexColor * uTint 결과에 곱한다. 다음 설정은 app.run(config) 앞에 둔다. GLSL이 그 값을 실제로 읽어야 설정에 성공한다.

config.renderConfig.bindUniforms = [](const graphics::DrawUniformContext& draw) {
    return draw.setUniform("uBrightness", 0.8f);
};

실습 29 광원만 확장할 때

내장 GLSL에서 RenderOptions의 조명과 점광원을 사용한다. 점광원과 표시 물체에 같은 월드 위치를 보낸다. 처음에는 카메라 화면의 우측 상단에 보이도록 배치한다. R은 공전 토글, N/F는 반경 감소·증가, +/−는 강도 조절이다. 현재 위상을 보존한 채 반경만 바꾸면 같은 방위에서 가까워지거나 멀어진다. 점광원을 하나 등록한 뒤 pointLights[0]를 갱신한다. 색조가 어두워 보여도 변환을 먼저 확인하며, 빛의 색이나 강도를 바꾸는 조건은 그 다음에 처리한다.

9. 안 될 때 첫 오류부터 찾기

증상 먼저 확인 조치
C1189 또는 C1083, 헤더를 찾지 못함 실제 헤더의 상위 루트, 현재 구성과 x64 GL/glew.h 등을 포함할 수 있도록 C/C++ 추가 포함 경로를 수정한다.
PCH 오류 C1010 gllib.cpp가 pch.h를 요구받는지 해당 파일의 PCH 설정을 사용 안 함으로 바꾼다.
LNK1104, 또는 __imp_glfw… 링크 오류 x64 glfw3dll.lib 파일과 라이브러리 경로 LIB 위치를 연결한다. glfw3.lib는 이 가이드의 DLL 가져오기 라이브러리와 다르다.
main 중복·진입점 오류 컴파일 목록과 콘솔 하위 시스템 기본 main() 하나를 남긴다. gllib.cpp를 포함하고 별도로 컴파일하는 구성을 같이 쓰지 않는다.
실행하자마자 DLL 오류 EXE 부모 폴더, DLL 아키텍처, 같은 배포본 해당 x64 GLFW DLL을 실행 폴더에 둔다.
창 생성·초기화 실패 GLFW/WGL·GL 컨텍스트 원문 OpenGL 3.3 Core를 제공하는 드라이버 환경인지 확인한다. 먼저 기본 장면으로 돌아가 재현한다.
창은 뜨는데 장면이 비어 있음 initScene 성공, 카메라 위치·target, 물체의 최종 월드 위치 기본 큐브를 원점 근처에 놓고 한 단계씩 복구한다. 부모가 들어간 뒤 화면 밖으로 나가는지 확인한다.
OBJ만 실패 프로젝트 폴더의 obj, 파일명, 상대 경로, 로더 오류 미리보기의 성공 로그와 실제 메시를 본다. 최소 로딩에 성공한 뒤 색과 경첩을 추가한다.
빌드는 되는데 외부 GLSL만 실패 프로젝트/EXE 기준 shaders/와 두 파일 이름 config.shaderDirectory를 잠시 비워 내장 GLSL의 성공과 비교한다.
키를 떼도 계속 이동 PRESS 필터 앞의 RELEASE 처리, onFocus(false) 입력 상태부터 로그로 확인한 뒤 dt 누적을 본다.

콘솔에 단서가 부족하면 EXAM_RUN의 config에 임시로 config.diagnostics = {true, true};를 설정한다. 첫 실패 단계와 파일·줄 번호를 확인한다. 매 프레임 추적이 많으면 원인 확인 후 trace를 끈다. 컴파일 → 링크 → DLL 로드 → 컨텍스트 → 셰이더 초기화 → 장면 등록 → 변환·그리기 순서로 좁힌다.
