# 학습 로그: 논리 상태와 렌더링 표현 분리

- 날짜: 2026-09-09
- 관련 파이프라인 단계: CPU 애플리케이션 상태, 화면 표시를 위한 렌더링 표현
- 관련 파일: `Computer-Graphics_WarmmingUp2/Warm2-1.cpp`, `Computer-Graphics_WarmmingUp2/BoardRenderer.cpp`

## 문제-해결 1

### 문제

보드 경계를 넘어간 사각형을 처리할 때, 이동으로 유지되는 논리적 사각형 상태와 화면에서 경계를 나누어 그리는 표현을 구분해야 했다. 두 책임이 섞이면 화면 래핑을 위해 사각형의 크기나 논리 상태까지 바뀔 수 있다.

### 원인

확인된 원인은 이동·크기 변경을 담당하는 상태 로직과 경계에서 보이는 구간을 나누는 렌더링 로직의 책임이 서로 다르다는 점이다. 이 구분을 실제 OpenGL 렌더링 파이프라인의 좌표·클리핑 단계와 연결해 설명할 수 있는지는 아직 확인하지 않았다.

### 해결

`Board::moveRectangle()`은 위치만 변경하고, `BoardRenderer::splitAxis()`는 논리 상태를 수정하지 않은 채 경계를 넘는 축을 화면에 표시할 구간으로 나눈다. 크기 변경은 별도 연산으로 유지하며, 실패한 크기 변경은 후보 상태를 먼저 검증한 후 전체를 거부한다.

### 이해 확인

사용자가 래핑을 렌더링 전용 동작으로 명확히 지정했고 이동과 크기 변경을 분리하는 계약을 확정했다. 다만 이 원칙을 새로운 OpenGL 예제에 스스로 적용하는지는 확인 필요하다.

### 남은 혼동과 다음 복습

남은 확인 사항은 이 CPU 측 표현 분리가 OpenGL의 클립 공간, 클리핑, 뷰포트 변환과 각각 어떻게 다른지 설명할 수 있는지이다.

다음 회상 질문: “사각형이 화면 오른쪽 경계를 넘었을 때, 논리 좌표를 두 사각형으로 바꾸는 방식과 렌더링할 때만 두 구간으로 나누는 방식은 이후 이동과 크기 변경에 어떤 차이를 만들까?”
