## 문제-해결 1: VAO와 버퍼 업로드

### 문제

사용자가 `upload()`의 `glBufferSubData()`가 “vao, vbo, ebo 순으로 4번” 호출되는 것인지 물었다.

### 원인

VAO의 정점 입력 설정과 VBO/EBO의 실제 데이터를 같은 저장 대상으로 본 점이 대화에서 확인됐다. `glGen...(1, ...)`의 `1`이 객체 수라는 점도 별도로 질문했다.

### 해결

현재 코드에서 위치 VBO·색상 VBO에 각각 1번, 선택이 있을 때 EBO에 1번만 `glBufferSubData()`를 호출한다. VAO에는 호출하지 않는다. `glGenVertexArrays(1, &vao_)`와 `glGenBuffers(1, &ebo_)`의 첫 인자는 생성 개수다.

### 이해 확인

확인 필요. 설명 뒤 사용자의 독립적인 코드 추적은 아직 받지 않았다.

## 문제-해결 2: 인덱스 순서와 기본도형 종류

### 문제

사용자가 EBO `[0,1,2,3 | 0,1,3,2]`의 뒤 절반이 앞 절반을 덮는지, 본체의 `1→2` 대각선이 보이지 않는 이유, 선택하지 않은 도형을 EBO로 통일하면 중복 정점이 줄지 않는지 질문했다.

### 원인

EBO의 방문 순서와 draw mode의 기본도형 조립 규칙을 분리해야 했다. `GL_TRIANGLE_STRIP` 본체는 두 삼각형을 채우고, `GL_LINE_LOOP` 외곽선만 연속한 인덱스를 선으로 잇는다. 현재 도형의 본체 VBO에는 제거할 중복 정점이 거의 없다.

### 해결

EBO의 두 구간은 모두 남는다. 앞 `0,1,2,3`은 삼각형 strip으로 채우고, 뒤 `0,1,3,2`는 좌하→우하→우상→좌상→좌하 선분으로 연결한다. `GL_LINE_LOOP`은 인덱스를 자동 재정렬하지 않는다. `glDrawElementsBaseVertex()`의 EBO 바이트 오프셋과 VBO 기준 정점 번호를 별개 단위로 설명했다. 전체 EBO 통일은 가능하지만 현재 단순 도형에서 정점 절감 효과는 작고 인덱스 범위 관리가 추가된다.

### 이해 확인

확인 필요. 사용자가 내부 대각선의 예상 결과를 말했으나, draw mode 차이를 반영해 다시 예측한 답은 아직 없다.

### 남은 혼동과 다음 복습

다음 회상 질문: “같은 EBO 순서 `0,1,2,3`을 `GL_TRIANGLE_STRIP`과 `GL_LINE_LOOP`으로 각각 그리면 무엇이 달라지는가?”

## 문제-해결 3: 저장소 변경 번호와 화면 그리기

### 문제

사용자가 `revision_`과 `uploadedRevision_`의 비교·대입 순서 및 지속 증가에 따른 범위 초과·전체 재렌더 비용을 물었다.

### 원인

저장소 상태 변경, GPU 버퍼 업로드, 매 프레임 draw call이 서로 다른 단계인데 하나의 “다시 그리기”로 묶어 이해할 가능성이 질문에서 드러났다.

### 해결

`revision_`은 상태 변경 때 증가하고 `uploadedRevision_`은 업로드 성공 후에만 그 값으로 갱신된다. 두 값이 다를 때만 `upload()`를 호출하되 `shader_.render()`는 매 프레임 실행한다. 부호 없는 64비트 순환 자체는 C++에서 정의되며 `!=` 비교는 일반적인 한 번의 순환에서 차이를 감지한다. 이 과제에서 실제 개선 대상은 선택 변경에도 전체 도형의 위치·색상 데이터를 재구성하는 부분이다.

### 이해 확인

확인 필요. 사용자는 비용과 범위 초과 위험을 비판적으로 제기했지만 단계별 재설명은 아직 확인하지 않았다.

## 문제-해결 4: 변환 중심과 셰이더 uniform

### 문제

사용자가 `worldVertices()`의 `pivot + R × S × (local - localPivot)` 공식, `glUniform1i`·`glUniform3f`가 어떤 GLSL 변수에 연결되는지 질문했다.

### 원인

로컬 회전 중심과 최종 위치, 셰이더 변수 이름·위치 번호·전달값의 역할을 각각 구분해야 했다. 이해하지 못한 원인을 사용자 능력으로 단정하지 않는다.

### 해결

`localPivot`을 빼 중심을 원점으로 옮긴 다음 크기·회전 후 `pivot`을 더해 최종 위치로 이동한다고 설명했다. `glGetUniformLocation()`이 `uUseOverrideColor`와 `uOverrideColor`의 위치를 찾고, `glUniform1i`는 bool용 정수 1개, `glUniform3f`는 RGB 실수 3개를 현재 프로그램에 전달한다고 연결했다.

### 이해 확인

확인 필요. 수치 변환 예제와 변수 매핑을 사용자가 스스로 계산·설명하지는 않았다.
