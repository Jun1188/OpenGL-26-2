# 학습 로그: Windows 작업 경로 오류

- 날짜: 2026-09-20
- 관련 파이프라인 단계: 해당 없음
- 관련 파일: `C:\Users\변준영\source\repos\openGL_sample2`

## 문제-해결 1

### 문제

`C:\Users\변준영\source\repos\openGL\_sample2`를 작업 디렉터리로 지정하여 명령을 시작하려 했을 때 Windows 오류 267(`디렉터리 이름이 올바르지 않음`)이 발생했다.

### 원인

확인 결과, 지정한 경로는 `openGL` 폴더 아래의 `_sample2` 폴더를 뜻하지만 해당 경로는 존재하지 않았다. 실제 프로젝트 폴더는 `openGL_sample2`라는 하나의 폴더이며 실제 경로는 `C:\Users\변준영\source\repos\openGL_sample2`이다.

존재하지 않는 경로를 프로세스의 작업 디렉터리로 전달했기 때문에 PowerShell 명령이 실행되기 전 Windows 프로세스 생성 단계에서 오류 267이 반환됐다. 프로젝트 코드나 OpenGL 렌더링 파이프라인에서 발생한 오류는 아니다.

### 해결

작업 디렉터리를 실제 존재하는 다음 경로로 지정한다.

`C:\Users\변준영\source\repos\openGL_sample2`

비슷한 오류가 발생하면 먼저 `Test-Path -LiteralPath '<경로>'`로 전체 경로의 존재 여부를 확인하고, 상위 폴더를 조회하여 폴더명이 분리됐는지 또는 밑줄 위치가 잘못됐는지 확인한다.

### 이해 확인

확인 필요. 사용자가 원인과 해결 방법을 직접 설명한 기록은 아직 없다.

## 문제-해결 2

### 문제

사용자는 쿼리에서 경로를 지정했는데 에이전트가 작업 디렉터리로 사용할 때 경로를 잘못 읽는 문제가 자주 발생한다고 지적했다. 특히 일반 문장에 작성된 `openGL\_sample2`가 화면에서는 `openGL_sample2`처럼 보일 수 있지만, 도구에는 역슬래시가 포함된 원문이 전달되어 서로 다른 경로로 처리될 가능성이 있었다.

### 원인

확인된 사실은 다음과 같다.

- 쿼리에서 받은 끝부분은 `openGL\_sample2`이며, 역슬래시 `U+005C`와 밑줄 `U+005F`가 모두 포함되어 있었다.
- `C:\Users\변준영\source\repos\openGL\_sample2`와 중간 폴더 `C:\Users\변준영\source\repos\openGL`은 존재하지 않았다.
- 실제로 존재하는 폴더는 `C:\Users\변준영\source\repos\openGL_sample2`였다.
- CommonMark에서는 일반 문장에 있는 `\_`를 이스케이프된 밑줄로 표시할 수 있다. 코드 구간에서는 역슬래시 이스케이프가 작동하지 않는다.
- Windows 경로에서는 역슬래시가 디렉터리 구분자이므로 `openGL\_sample2`는 `openGL` 폴더 아래의 `_sample2` 폴더를 뜻한다. `openGL_sample2`라는 단일 폴더명과 같지 않다.
- `-LiteralPath`는 받은 문자열을 그대로 사용하므로 Markdown 이스케이프를 자동으로 제거하지 않는다.

따라서 화면 표시에서는 경로가 정상처럼 보이지만 원문에는 추가 역슬래시가 남는 표현 계층 차이가 반복 오류의 유력한 원인이다. 다만 Codex 앱이 사용자 입력을 표시하고 모델에 전달하는 내부 절차는 공식 OpenAI 문서에서 확인하지 못했으므로, 이 부분은 현재 관찰에 근거한 추론으로 구분한다.

### 해결

사용자가 Windows 경로를 전달할 때는 실제 경로에 없는 역슬래시를 밑줄 앞에 추가하지 않고, 전체 경로를 Markdown 코드 구간으로 감싼다.

`C:\Users\변준영\source\repos\openGL_sample2`

에이전트는 경로를 작업 디렉터리로 사용하기 전에 다음 순서로 확인한다.

1. 받은 원문 경로를 `Test-Path -LiteralPath`로 검사한다.
2. 원문이 존재하지 않고 `\_`가 포함돼 있으면, `\_`를 `_`로 바꾼 후보 경로를 읽기 전용으로 검사한다.
3. 후보 하나만 존재하면 원문과 후보의 차이를 사용자에게 알린 뒤 후보를 사용한다.
4. 원문과 후보가 모두 존재하거나 둘 다 존재하지 않으면 자동으로 선택하지 않는다.
5. 파일 수정, 이동, 삭제 같은 변경 작업에서는 후보를 자동 확정하지 않고 정확한 대상 경로를 다시 확인한다.

### 이해 확인

부분 확인. 사용자가 화면에 표시된 경로와 작업 디렉터리로 읽힌 경로의 차이가 반복된다고 직접 지적했다. Markdown 이스케이프와 Windows 디렉터리 구분자의 차이를 사용자가 직접 설명할 수 있는지는 확인이 필요하다.
