# 실습 22: 동일 탱크 장면의 세 가지 투영

`lecture_pdf/homework/지엘3 좌표계 변환 (실습 2122).pdf` 3쪽을 기준으로 구현했다. `openGL_3dAssign_19/Console.h`와 `Console.cpp`의 전체 탱크 및 입력 동작을 재사용했다. 실습 19 원본은 수정하지 않았다.

## 요구사항과 구현

| 요구사항 | 구현 위치 | 기대 결과 |
|---|---|---|
| 실습 19 장면을 세 뷰포트에 출력 | `Console::reset`, `Console::onRender` | 바닥, 아래 몸체 2개, 중앙 몸체, 위 몸체 2개, 포신 2개, 막대 2개가 같은 Scene에 존재 |
| 뷰 1 원근 투영 | `PatternSystem::threeViews`의 첫 RenderPass | 왼쪽 2/3에 원래 장면 표시 |
| 뷰 2 XZ 평면도 | 두 번째 RenderPass | 오른쪽 위, +Y에서 아래 방향을 봄. up=-Z |
| 뷰 3 XY 정면도 | 세 번째 RenderPass | 오른쪽 아래, +Z에서 -Z 방향을 봄. up=+Y |
| XZ 이동을 세 뷰에 동일 반영 | `onUpdate`에서 root 위치 갱신 후 `renderViews` | 한 월드 좌표의 탱크를 다른 방향에서 표시 |
| 리사이즈와 작은 프레임버퍼 처리 | `getFramebufferSize`와 `onRender` | 현재 픽셀 크기로 패스 재생성. 3x2 미만이면 그리기만 건너뜀 |

정면도에서 Z 이동은 화면의 깊이 방향이다. 따라서 XZ 평면도처럼 화면 위아래로 움직이지 않는 것이 정상이다. 세 뷰의 동일 반영은 화면 픽셀 이동량이 같다는 뜻이 아니라, 같은 월드 위치와 부품 상태를 사용한다는 뜻이다.

## 키

영문 대소문자 방향은 Shift와 Caps Lock의 XOR로 결정한다. 방향이 없는 기능 키는 대소문자 모두 같다. 자동 키 반복은 기능을 다시 토글하지 않는다.

| 키 | 동작 |
|---|---|
| ← / → | 탱크의 월드 X 감소 / 증가. 누르는 동안 이동 |
| ↑ / ↓ | 탱크의 월드 Z 감소 / 증가. 누르는 동안 이동 |
| D / d | 아래 몸체의 높이 변화 시작 / 정지. 중앙과 위 부품도 높이를 따라감 |
| T / t | 중앙 몸체와 자식들의 Y축 회전 시작 / 정지 |
| G / g | 두 포신의 반대 방향 Y축 회전 시작 / 정지 |
| P / p | 두 막대의 반대 방향 X축 왕복 회전 시작 / 정지 |
| L / l | 두 위 몸체 위치 교환 시작. 진행 중 누르면 정지 / 재개. 끝에서 누르면 반대 방향으로 교환 |
| x / X | 카메라 월드 +X / -X 이동. 누르는 동안 이동 |
| z / Z | 카메라 월드 +Z / -Z 이동. 누르는 동안 이동 |
| y / Y | 카메라 로컬 up축 - / + 자전 시작. 같은 대소문자 키를 다시 누르면 정지 |
| r / R | 월드 원점을 지나는 Y축 - / + 공전 시작. 같은 대소문자 키를 다시 누르면 정지 |
| O / o | 모든 상자의 색상 팔레트 변경. 실습 19 안내의 대문자 입력도 처리 |
| C / c | 탱크 위치·관절·동작 토글·입력·카메라·색·렌더 옵션 초기화 |
| Q / q / Esc | 종료 |

탱크 중심은 X와 Z 각각 [-3.5, 3.5] 범위다. 대각선 이동은 정규화하므로 이동 속도가 증가하지 않는다. 포커스를 잃으면 방향키와 x/z 누름 상태를 해제한다. D/T/G/P/L 및 y/r로 시작한 연속 동작은 토글 상태를 유지한다.

카메라 이동과 회전은 공통 API가 제공한다. 평면도·정면도의 중심은 원근 카메라의 주목점을 공유한다. x/z 카메라 이동 또는 y 자전 시 보조 뷰의 중심도 이동할 수 있다. C로 기본 시점을 복원한다.

## 호출 흐름

1. `main`은 `Application`과 `Console`을 생성하고 초기화·수정키·업데이트·포커스·렌더 콜백을 등록한다.
2. `Application::run`이 컨텍스트를 만든 뒤 `initScene`을 호출한다. `reset`은 Scene을 비우고 새 ID로 전체 탱크를 조립한다.
3. 입력은 `onKey`에서 누름 상태 또는 동작 토글을 바꾼다. 한 프레임의 `onUpdate(dt)`가 탱크 위치, 높이, 관절 각도, 교환 진행률, 카메라를 한 번만 갱신한다.
4. `apply`가 root의 월드 이동과 자식의 부모 로컬 변환을 Scene에 반영한다. 중앙 관절은 높이 위치, 포신 관절은 위 몸체 중심 `(0,.3,0)`, 막대 관절은 밑점 `(0,.6,0)`을 유지한다.
5. `Application::run`이 Scene 모션을 한 번 갱신한다. 이 실습은 별도로 `updateMotions`를 호출하지 않는다.
6. `onRender`는 현재 프레임버퍼 크기로 세 RenderPass를 만든다. `renderViews`는 같은 Scene을 세 번 그린다. 각 패스의 aspect·viewport·scissor·색/깊이 지우기는 프레임워크가 처리한다.
7. 공통 렌더러는 Scene의 모델·월드 변환을 VAO/VBO/EBO와 셰이더에 전달한다. 모델→월드→뷰→클립 변환 뒤 각 뷰포트에 출력한다.
8. `run` 종료 시 프레임워크가 GL 자원과 창을 정리한다. 콜백 또는 초기화 예외는 정리 후 `main`으로 전달되어 구체적인 원인을 콘솔에 출력한다.

`Scene`은 한 벌이다. 렌더 콜백에서는 시간·이동·관절 상태를 갱신하지 않는다. 포신은 몸체 중심 관절에 원래 오프셋을 자식 위치로 옮겨 붙였으므로 `rotateJoint`만으로 원래 피벗 회전을 표현한다.

## 사용하는 공통 API

- `PatternSystem::addBox`: 중심 기준 상자. 실패한 optional은 문맥이 있는 예외로 처리한다.
- `addJoint`, `rotateJoint`: 부모 로컬 기준 연결점과 절대 회전각.
- `moveCamera`, `yawCamera`, `orbitCamera`: 카메라 후보가 유효할 때만 변경.
- `threeViews`, `Application::renderViews`, `getFramebufferSize`: 같은 Scene의 세 투영과 framebuffer 픽셀 기준 분할.
- `Scene::setPosition`, `setTransform`, `setTint`: 실패 시 예외를 전달한다.

공통 기반은 `fd79f92`다. 이 폴더의 `framework/`를 그대로 사용한다. 프레임워크 파일은 이 실습 구현에서 수정하지 않았다.

## 프로젝트와 확인 상태

`openGL_assign_22.sln` 또는 지원되는 Visual Studio에서 `openGL_assign_22.slnx`를 연다. Debug/Release x64, C++17, 정적 CRT(/MTd, /MT)를 사용한다. `Microsoft.Cpp.Default.props` 다음에 로컬 `framework/Toolchain.props`를 가져오며 특정 v145를 고정하지 않는다. 프로젝트와 의존 경로는 모두 상대 경로다. 외부 SDK 설치나 사용자별 절대 경로가 필요하지 않도록 구성했다.

빌드·실행·테스트·검증기는 실행하지 않았다. 소스와 과제 본문만 읽었다. 실제 창·GPU·DLL·다른 PC 호환성은 미확인이다. 사용자가 `USER_CHECKS.md`의 순서로 확인해야 한다.

학습 확인: Z 이동 시 XZ 평면도에서는 화면 위치가 바뀌지만 XY 정면도에서는 깊이가 바뀌는 이유를 모델→월드→뷰 좌표 순서로 설명해 본다.
