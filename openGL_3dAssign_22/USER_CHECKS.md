# 사용자 확인 절차: 실습 22

에이전트는 빌드·실행·테스트·검증기를 실행하지 않았다. 아래 항목은 사용자가 직접 수행할 절차와 기대 결과다. 아직 통과로 표시하지 않았다.

## 빌드와 실행

1. `openGL_assign_22.sln`을 열고 Debug x64를 빌드한다. 설치된 Visual Studio 툴셋을 사용하고 외부 SDK 경로나 v145 강제 지정이 없어야 한다. 실행 파일은 `x64/Debug/openGL_assign_22.exe`다.
2. Release x64도 빌드한다. 실행 파일은 `x64/Release/openGL_assign_22.exe`다. 두 구성 모두 프레임워크 런타임 DLL이 실행 폴더 아래로 복사되어야 한다.
3. 두 실행 파일을 각각 실행한다. 콘솔에 키 안내가 나오고 왼쪽 원근, 오른쪽 위 XZ 평면도, 오른쪽 아래 XY 정면도가 보여야 한다. 초기 시점은 `(-5,4.5,7)`, 주목점은 `(0,.7,0)`이다.
4. 초기 전체 탱크에서 아래 몸체 2개, 중앙 몸체, 위 몸체 2개, 포신 2개, 막대 2개와 바닥을 확인한다. 보조 뷰의 직각 투영 반범위는 6.5다.

## 같은 Scene의 이동과 관절

1. C로 초기화한다. ←/→를 누르면 세 뷰가 같은 월드 X 위치를 표시해야 한다. ↑/↓는 월드 Z 위치를 바꾼다. XZ 평면도에서는 앞뒤 이동이 보여야 한다. XY 정면도는 Z를 깊이로 투영하므로 화면 Y 이동이 없어야 한다.
2. 대각선 방향키를 누른다. 단일 축보다 전체 이동 속도가 빨라지지 않아야 한다. 바닥 끝에서는 중심이 X/Z ±3.5에서 멈춰야 한다.
3. D로 높이 변화를 시작한다. 아래 몸체 밑면은 바닥에 남고 중앙·위 부품은 높이를 따라가야 한다. 다시 D를 눌러 멈춘다.
4. T로 중앙 회전을 시작한다. 위 몸체·포신·막대가 함께 회전하고 아래 몸체는 중앙 회전의 자식으로 돌지 않아야 한다.
5. G를 누른다. 두 포신이 각각 위 몸체의 중심을 기준으로 반대 방향으로 회전해야 한다. 포신 자체 중심이나 월드 원점을 피벗으로 돌면 실패다.
6. P를 누른다. 막대의 밑점은 고정되고 좌우 막대가 반대 방향으로 왕복 회전해야 한다.
7. L로 위 몸체 위치 교환을 시작하고 중간에 L로 멈춘다. 다시 L로 재개한다. 끝에 도달하면 멈추고, 다시 누르면 반대 방향으로 돌아와야 한다. 포신·막대가 위 몸체를 따라가야 한다.
8. D/T/G/P/L을 조합한다. 세 뷰에 같은 시간의 부품 상태가 표시되어야 한다. 프레임워크는 업데이트 한 번, 렌더만 세 번 수행하므로 세 뷰 때문에 속도가 3배가 되면 실패다.

## 키와 초기화

1. x/X, z/Z를 누르는 동안 카메라가 +/− 축으로 움직이고 놓으면 멈추는지 확인한다. Caps Lock만 켠 경우와 Shift+Caps Lock을 함께 켠 경우도 확인한다.
2. y/Y, r/R로 각 방향의 자전·공전을 시작하고 같은 대소문자를 다시 눌러 멈춘다. 반대 대소문자를 누르면 반대 방향으로 바뀌어야 한다. 보조 뷰는 공통 카메라 주목점 중심을 공유한다.
3. 방향키 또는 x/z를 누른 상태에서 다른 창으로 포커스를 이동하고 키를 놓는다. 다시 돌아오면 해당 누름 이동이 남지 않아야 한다. 토글로 시작한 연속 동작은 유지된다.
4. O와 o 모두 팔레트를 바꿔야 한다. 기능 키를 길게 눌러도 OS 반복 입력으로 여러 번 토글되지 않아야 한다.
5. 여러 동작과 카메라 이동 후 C를 누른다. 모든 동작이 멈추고 탱크·색상·관절·시점·입력 상태가 초기화되어야 한다. 세 뷰 모두 같은 초기 장면으로 돌아와야 한다.
6. Q와 Esc 각각으로 정상 종료되는지 확인한다.

## 창 크기·최소화·DPI

1. 창을 가로·세로 방향으로 늘리고 줄인다. 왼쪽 2/3와 오른쪽 위/아래 분할이 현재 framebuffer 픽셀에 맞게 유지되어야 한다. 비율이 달라도 물체가 늘어나지 않아야 한다. 매우 좁은 뷰에서는 시야 밖 물체가 잘릴 수 있다.
2. 최소화 후 복원한다. 프레임버퍼가 3x2 미만인 동안 그리기를 건너뛰고, 복원 후 종료나 오류 없이 세 뷰가 다시 나타나야 한다.
3. Windows 배율 100%와 150% 또는 200% 환경에서 실행한다. 서로 다른 DPI 모니터가 있으면 창을 옮긴다. 경계에 잔상·깊이 버퍼 간섭·화면 일부 미갱신이 없어야 한다.
4. 창 크기를 바꾼 뒤에도 방향키 이동과 관절 동작이 같은 Scene을 세 번 투영해야 한다.

## 다른 경로와 PC

1. 소스 폴더 전체와 그 안의 `framework/`를 다른 경로로 복사한다. 해당 PC의 Visual Studio C++ 도구와 Windows SDK 환경에서 Debug/Release x64를 각각 빌드한다. 원래 PC의 절대 경로나 별도 SDK 디렉터리 편집이 없어야 한다.
2. 생성된 실행 파일만 옮기지 말고 실행 파일 폴더의 `framework/` 런타임도 함께 복사한다. OpenGL 3.3 core를 지원하는 드라이버에서 실행한다.
3. 위 세 뷰, 이동, 관절, 키, 초기화, 창 크기 항목을 다시 확인한다. 실패하면 구성·툴셋·GPU·드라이버·콘솔의 단계/API/원인 메시지를 기록한다.
