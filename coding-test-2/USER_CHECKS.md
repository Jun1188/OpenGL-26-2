# 사용자가 수행할 확인

에이전트는 아래 빌드·테스트·앱·브라우저 실행을 수행하지 않았다.

- native/native.sln과 standard/standard.sln을 x64에서 각각 빌드한다. GLEW/GLFW DLL과 GLSL이 실행 폴더에 복사되는지 본다. 순정은 자체 native 폴더만 다른 경로로 옮긴 사본도 확인한다.
- Standard 시작 후 m/c/y/Y/z/Z/WASD/r/R/p/F2/Space/Home을 확인한다. 궤도·표시 물체·광원이 일치해야 한다. 폴더 내부 debugger를 별도로 빌드하고 where state/input/update/uniform/shader 및 객체 편집 제안의 before/행 번호를 소스와 대조한다.
- index.html을 더블클릭해 오프라인에서 설명·12문항·6시나리오·전체 소스가 열리는지 확인한다. 힌트와 해설 펼치기, 코드 복사, 타이머, 진도 저장을 확인한다. 브라우저의 file:// 로컬 저장 정책에 따라 진도는 저장되지 않을 수 있고 자료 열람은 계속 가능해야 한다.
- 각 문항의 코드는 지정한 원본에 적용하는 독립 연습이다. 모든 문제 코드를 같은 프로젝트에 한꺼번에 붙여 넣지 않는다. 문항 전에 작업 복사본을 만들거나 자신의 변경을 커밋해 비교한다.
- 제출 ZIP을 별도 경로에 풀어 debugger/docs/학습 HTML이 없고 SDK/DLL/GLSL이 있는지 확인한다. Standard만 단독 빌드·실행한다. 압축 해제 후 논리 파일 크기와 SIZE 보고서를 비교한다.
- 실행 관찰 결과를 코드 작성 여부와 구분해 기록한다. 막힌 지점은 입력 사건→상태→좌표계→행렬→uniform→화면 순서로 추적한다.

임시 PDF 이미지 캐시는 열람 근거로 보존했다. 사용자 소스·백업·SDK·기존 문서 ZIP을 삭제하지 않았다.
