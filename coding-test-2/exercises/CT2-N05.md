# CT2-N05 · 입력 규칙과 카메라의 상태 분리

경로: native · 권장 30분(실제 시험 시간 아님)

## 문제

WASD는 누르는 동안 움직이고, r/R은 공전을 토글한다. 대각 이동 속도를 축 이동과 같게 한다. 창 포커스를 잃어도 이동이 계속 남지 않아야 한다. 카메라 위치만 이동하는 모드와 주목점도 같이 이동하는 모드를 만든다.

## 상태·공간 설계

held 배열과 토글 direction은 별개다. mode는 PRESS에서 한 번만 변경한다. 카메라 position-target 차이는 공전 반경벡터다. 관찰 지점 유지와 평행 이동은 서로 다른 요구다.

## 단계별 힌트

1. GLFW 키 코드는 대문자/소문자 구분 없이 GLFW_KEY_R이고 Shift는 mods다.
2. 카메라와 target에 같은 delta를 더하면 시선 방향이 유지된다.

## 해설과 수정 코드

State에 `bool translateTarget=false;`를 추가하고 key의 PRESS 구간에 넣는다.
```cpp
if(key==GLFW_KEY_T) state.translateTarget=!state.translateTarget;
```
update에서 기존 카메라 직선 이동 두 줄을 다음으로 대체한다.
```cpp
auto move=glm::vec3(int(state.move[3])-int(state.move[1]),0,
    int(state.move[2])-int(state.move[0]));
if(glm::length(move)>0) {
    const auto delta=glm::normalize(move)*3.f*dt;
    state.camera+=delta;
    if(state.translateTarget) state.target+=delta;
}
```
그 뒤의 target 기준 공전 코드는 보존한다. 공전과 평행 이동을 함께 쓰면 기준점도 이동한다. focus 콜백의 move.fill(false)는 보존한다. 같은 키를 한 번 누른 사건으로 움직임 거리를 누적하면 OS 키 반복 속도에 의존한다.

## 사용자가 확인할 결과

- [ ] w+d 이동이 w 이동보다 빠르지 않다.
- [ ] T 모드에서 이동 후에도 카메라-주목점 벡터가 같다(공전 정지 상태).
- [ ] 포커스를 잃었다 돌아오면 키를 다시 누를 때까지 이동하지 않는다.
