# CT2-N12 · debugger 안내로 소스와 셰이더 직접 편집

경로: standard · 권장 45분(실제 시험 시간 아님)

## 문제

debugger를 실행해 새 박스 생성·비균등 배율·지역 피벗·조명 변경의 실제 파일/행/before/after를 확인한다. 이어서 where로 상태·입력·uniform·GLSL 위치를 찾고 밝기 배율 uniform 하나를 직접 연결한다. debugger가 소스를 대신 저장하지 않는 것을 확인한다.

## 상태·공간 설계

구조화 명령은 SceneSetup의 @debug 구획을 읽는다. where는 실제 hook을 검색한다. 임의 셰이더 수정은 code/replace/insert로 제안할 수 있지만 uniform 의미까지 자동으로 판단하지 않는다.

## 단계별 힌트

1. 새 object 제안을 수동 저장해야 그 이름을 다음 명령이 찾는다.
2. where uniform은 CPU 위치, where shader는 실제 외부 GLSL과 내장 사본을 구별한다.

## 해설과 수정 코드

사용자가 debugger/debugger.sln에서 빌드한 뒤 자기 경로의 debugger.exe에 Standard 폴더를 인수로 전달한다. 콘솔에서 다음 순서로 입력한다.
```text
add object practicePanel box
show object practicePanel
object practicePanel position 2 1 0
object practicePanel scale 2 1 0.5
add layer practiceHinge practicePanel
layer practiceHinge pivot -0.5 0 0
layer practiceHinge rotation 0 45 0
light key color 1 0.3 0.2
where state
where input
where uniform
where shader
```
각 add와 변경 명령 사이에 **실제 before를 읽고 after를 IDE에 붙여 저장**한다. practicePanel의 기본 size가 1이므로 지역 x=-.5는 왼쪽 끝이다. 행 번호는 매 명령 때 디스크에서 계산한다. 앞에 빈 줄을 넣어 저장하고 재입력하면 번호가 이동해야 한다.

밝기 조절은 ExamController State에 `float extraGain=1;`를 넣는다. onKey PRESS 구간에 `if(key==GLFW_KEY_G) state_.extraGain=state_.extraGain==1 ? 1.5f : 1;`를 넣는다. bindUniforms 반환을 바꾼다.
```cpp
return context.setUniform("uStudyView",state_.shaderView)
    && context.setUniform("uExtraGain",state_.extraGain);
```
외부 FragmentShader.glsl에 `uniform float uExtraGain;`를 선언한다. 최종 `FragColor = color;` 바로 앞에 `color.rgb *= uExtraGain;`를 넣는다. 내장 셰이더만 수정하면 이 Standard의 외부 셰이더 경로에는 반영되지 않는다. 빌드·실행은 사용자가 한다.

## 사용자가 확인할 결과

- [ ] 모든 before가 저장된 소스와 같고 after는 복사 가능한 코드다.
- [ ] debugger를 삭제한 복사본에서도 Standard 프로젝트는 도구를 참조하지 않는다.
- [ ] g 동작과 F2 출력이 함께 유지된다.
