# 사용자 확인: 실습 21

아래 절차는 사용자가 직접 수행한다. 에이전트는 빌드·실행·테스트·검증기를 실행하지 않았다. 아직 통과한 항목은 없다.

1. `openGL_assign_21.sln`에서 Debug x64를 빌드·실행한다. 같은 방법으로 Release x64도 확인한다. 두 구성에서 framework 상대 경로를 사용하고, 출력 폴더 아래 framework/dependencies에 실행 DLL이 배치되어야 한다. 실패 시 최초 진단 단계·API·원인과 콘솔 출력을 기록한다.
2. 초기 화면에서 앞면이 없는 직육면체 내부와 서로 다른 색의 왼쪽·오른쪽·위·아래·뒤 면을 확인한다. 원근감, 뒤쪽 물체 가림, 안쪽 면의 표시를 관찰한다. 공 1개와 Z축 일렬의 서로 다른 크기 상자 3개가 있어야 한다.
3. 공이 왼쪽·오른쪽·위·아래·앞·뒤 물리 경계에서 방향을 바꾸는지 확인한다. 반지름이 벽을 관통하지 않아야 한다. +Z 앞면은 시각적으로 열려 있어도 반사 경계다. 객체끼리 충돌하지 않는 것은 문서에 명시된 한계다.
4. B를 4번 누르면 총 5개가 된다. 이후 B를 여러 번 눌러도 6번째는 생성되지 않아야 한다. B를 길게 눌렀을 때 키 반복으로 여러 공이 생기지 않아야 한다. 생성 순간 기존 미이탈 객체와 겹치지 않아야 한다. 낙하한 공도 최대 수에 포함된다.
5. 왼쪽 버튼을 누르고 왼쪽으로 드래그한다. 앞에서 볼 때 공간이 반시계로 기울고 상자가 바닥을 따라 낮은 쪽으로 움직여야 한다. 오른쪽 드래그는 반대다. 드래그 정지 뒤에도 기울어진 바닥에 중력이 작용한다. 버튼을 놓으면 각도 변경이 멈춰야 한다.
6. 드래그 도중 Alt+Tab으로 다른 창으로 전환한다. 돌아온 뒤 클릭 없이 마우스만 움직이면 공간이 회전하지 않아야 한다. 포커스가 없는 동안 물리 계산이 멈추고, 돌아올 때 큰 시간 점프로 튀지 않아야 한다.
7. Caps Lock을 끈 상태에서 z와 Shift+z를 누른다. 카메라가 월드 Z 양/음 방향으로 이동해야 한다. y와 Shift+y로 시점 위치를 유지한 화면 로컬 Y 시계/반시계 자전을 확인한다. Caps Lock을 켜면 단독 키 방향이 바뀌고 Shift까지 누르면 소문자 방향으로 돌아와야 한다. 카메라 키를 길게 누르면 반복 이동이 적용되어야 한다.
8. R로 초기화한 뒤 F를 누른다. 바닥 면이 사라지고 상자는 낙하해야 한다. 공은 열린 바닥 경계에 도달한 뒤 중력 낙하해야 한다. F를 다시 누르면 바닥이 나타나지만 이미 떨어진 객체가 자동 복귀하지 않아야 한다. F를 길게 눌러도 바닥이 반복 토글되지 않아야 한다.
9. 회전·카메라 변경·공 추가·바닥 개방 뒤 R을 누른다. 각도 0, 바닥 닫힘, 원래 카메라, 상자 3개와 공 1개로 돌아와야 한다. 새 공을 5개까지 다시 생성할 수 있어야 한다. H 도움말, Q와 Esc 종료도 확인한다.
10. 창 크기를 바꾸고 최소화·복원한다. 가로세로 비율이 맞고 복원 뒤 오류가 없어야 한다. Windows 배율 100%와 150%에서 좌우 드래그 방향이 같고 첫 이동에 큰 각도 점프가 없어야 한다. 드래그는 논리 창 좌표 dx 기준이므로 같은 물리 픽셀 거리에서 각도는 배율에 따라 다를 수 있다.
11. 프로젝트 폴더를 공백·한글 경로로 복사하고 다른 Windows x64 PC에서 전체 framework와 함께 연다. 해당 PC에 설치된 지원 MSVC 도구 집합을 사용해야 한다. 외부 절대 경로나 별도 SDK 수동 설치 없이 컴파일·DLL 로드가 되는지 사용자가 확인한다.
