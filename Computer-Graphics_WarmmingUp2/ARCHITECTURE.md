# 문제 5~6 구조와 실행 흐름

## 전체 구성

시작점은 `FileName.cpp`입니다. `Application`이 메뉴와 입력 흐름을 담당하고 다음 객체에 실제 작업을 맡깁니다.

```text
FileName.cpp -> Application
  문제 5 -> BoardCommandParser -> Board -> BoardRenderer
  문제 6 -> MeshParser -> MeshValidator -> MeshReporter
```

입출력은 `Application` 멤버로 감싸지 않고 `std::cin`, `std::cout`을 직접 사용합니다.

## 문제 5: 사각형 보드

### 클래스와 상태

| 타입·변수 | 내용 |
|---|---|
| `Point { x, y }` | 사각형의 논리 시작 좌표. 이동으로 순환하면 음수가 될 수 있음 |
| `Size { width, height }` | 실제 크기. 각 축은 항상 1 이상이고 보드 크기 이하 |
| `Rectangle::position_`, `size_` | 한 사각형의 시작 좌표와 실제 크기 |
| `Board::rectangles_` | 사각형 두 개의 상태 |
| `Board::size_` | 현재 정사각형 보드 한 변의 길이 |
| `BoardFrame::cells` | 출력 직전에 만든 셀 배열. 모델 상태를 바꾸지 않음 |

순환 전용 크기는 저장하지 않습니다. 실제 크기는 `Rectangle::size_` 한 곳에만 있고, 순환 여부는 출력할 때 시작 좌표와 종료 좌표로 계산합니다.

### 명령

앞의 `1` 또는 `2`는 대상 사각형이며 생략하면 1번입니다.

| 명령 | 의미 |
|---|---|
| `x/X`, `y/Y` | 오른쪽/왼쪽, 아래/위 한 칸 이동 |
| `i/I`, `j/J` | 너비, 높이 한 칸 증가/감소 |
| `s/S` | 너비와 높이 동시 감소/증가 |
| `a/A` | 너비 증가·높이 감소 / 너비 감소·높이 증가 |
| `b`, `c/d`, `r/q` | 면적, 보드 확대/축소, 초기화/종료 |

`BoardCommandParser::parse()`는 한 줄에서 하나의 명령만 받고 `BoardCommand`에 대상, 종류, 변화량을 기록합니다.

### 이동과 순환

`Board::moveRectangle()`은 한 축의 한 칸 이동인지 검사한 뒤 해당 축의 시작점만 바꿉니다. `movedPosition()`은 도형 끝이 경계를 지나면 보드 크기를 더하거나 빼 논리 좌표로 순환을 표현합니다. 크기는 바꾸지 않습니다. 경계순환은 이동에서만 새로 생깁니다.

### 크기 변경과 전체 거부

`Board::resizeRectangle()`은 새 너비와 높이를 `next`에 함께 계산합니다.

1. 한 축이라도 1보다 작거나 보드보다 크면 전체 거부합니다.
2. 일반 위치의 확대가 어느 한 축에서 경계를 새로 넘으면 전체 거부합니다.
3. 이동으로 이미 순환 중인 축을 더 확대하려 하면 전체 거부합니다.
4. 두 축 검사가 모두 성공한 경우에만 새 `Rectangle`을 한 번 대입합니다.

따라서 높이가 1인 도형에 `a` 또는 `s`를 입력하면 한 축의 변경이 실패하므로 너비와 높이 모두 바뀌지 않습니다. `s/S`, `a/A` 모두 전체 성공 또는 전체 거부입니다.

### 순환 출력

`BoardRenderer::project()`는 각 축에서 다음 좌표를 비교합니다.

```text
화면 시작점 = wrap(논리 시작점)
화면 종료점 = wrap(논리 시작점 + 실제 길이 - 1)
```

시작점이 종료점보다 크면 경계를 지난 것이므로 `[시작점, 보드 끝]`과 `[0, 종료점]`으로 나눕니다. 가로·세로 구간을 조합해 셀을 채우고 두 도형이 겹치면 `overlap`으로 표시합니다.

### 보드 축소

`Board::resizeBoard(-1)`은 축소 후보를 만든 다음 모든 사각형에 `fitsInside()`를 적용합니다. 음수 논리 좌표를 포함해 하나라도 완전히 들어오지 않으면 보드 크기와 도형 상태를 모두 유지합니다.

## 문제 6: 메시 파일 검사

파일을 읽고 보고서를 한 번 만든 뒤 콘솔과 `outout-6`의 자동 번호 파일에 같은 내용을 기록합니다.

### 자료형

| 타입 | 내용 |
|---|---|
| `Vertex`, `Texture` | 3차원 정점 좌표와 2차원 텍스처 좌표 |
| `CornerIndex` | 정점 인덱스, 텍스처 인덱스, `hasTexture` |
| `TriangleIndices` | 면의 꼭짓점 세 개 |
| `VertexRecord`, `TextureRecord`, `FaceRecord` | 값, 원본 줄 번호, 문법상 유효 여부 |
| `Diagnostic` | 오류 줄, 면 번호, 메시지. 면과 무관하면 번호 0 |
| `ResolvedFace` | 참조한 실제 값까지 확인한 유효 면 |

잘못된 선언도 레코드 한 칸을 남겨 뒤 인덱스가 원본 선언 순서와 계속 일치하게 합니다.

### 파싱

`MeshParser::parse()`는 `v x y z`, `vt s t`, `f v1 v2 v3`, `f v1/t1 v2/t2 v3/t3`을 처리합니다. 빈 줄, `#` 주석, UTF-8 BOM을 허용합니다. 숫자 토큰 전체를 검사하고 `nan`, `inf`, 범위 초과를 거부합니다. 인덱스는 1 이상의 십진 정수만 받습니다. 오류가 나도 다음 줄을 계속 읽습니다.

### 검증

`MeshValidator::validate()`는 먼저 모든 정점 좌표가 `[-1,1]`, 텍스처 좌표가 `[0,1]`인지 검사합니다. 이어 각 면의 인덱스 범위, 참조 선언, 중복, 삼각형 성립 여부를 검사합니다.

중복은 현재 면의 세 꼭짓점 안에서만 검사합니다. 다른 면에서 좌표를 재사용할 수 있습니다. 한 면 안에서는 같은 정점 인덱스, 같은 정점 좌표, 같은 텍스처 좌표쌍을 거부합니다. 세 정점이 동일 직선 위인 경우만 삼각형이 아니라고 판정하며, 아주 작은 삼각형은 좌표 크기를 정규화한 뒤 판정합니다.

### 출력 파일과 전체 실패

`MeshReporter::print()`의 스트림 오버로드는 파서 오류, 검증 오류, 유효한 면, 요약을 `std::ostringstream`에 기록합니다. `Application::runMesh()`는 완성된 문자열을 콘솔과 파일에 동일하게 씁니다. 입력 파일의 stem 뒤에 `-1`, `-2` 순서로 빈 번호를 찾아 기존 결과를 덮어쓰지 않습니다. 오류가 하나라도 있거나 일부 면만 유효하면 보고서는 저장하되 `succeeded()`가 거짓이므로 종료 코드는 2입니다.

```text
Application::runMesh(path)
  -> 파일 열기 -> parse -> validate -> report string
  -> console + outout-6/(input-stem-number).txt
  -> 성공 0, 파일 오류 1, 검증 실패 2
```

## `Application` 실행 흐름

`Application::run()`은 인수가 없으면 메뉴를 반복합니다. `5`는 `runBoard()`, `6`은 경로를 받아 `runMesh()`를 호출합니다. `--board`, `--parse 파일경로`도 지원합니다. 모든 대화형 입력에 `getline`을 사용하므로 면적 출력 직후의 `q`도 정상 처리됩니다.

## 사용한 표준 라이브러리

- `string`, `vector`, `array`: 문자열, 가변 목록, 개수가 고정된 도형·삼각형
- `iostream`, `fstream`, `sstream`: 콘솔, 파일, 한 줄 해석
- `filesystem`: 한글을 포함한 Windows 경로
- `cmath`: 유한한 실수 확인과 삼각형 판정

직접 `new`나 `delete`를 사용하지 않습니다.
