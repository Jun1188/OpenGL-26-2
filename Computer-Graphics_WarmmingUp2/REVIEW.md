# 리팩토링 및 버그 검토 보고서

## 수정 내용

| 문제 | 원인 | 현재 처리 |
|---|---|---|
| 순환 중인 축에서 `S` 반복 시 보드 전체까지 확대 | 음수 논리 좌표를 확대 경계 검사에서 제외 | 순환 중인 축의 확대를 차단 |
| `a/A`, `s/S`에서 한 축만 변경 | 두 축을 차례로 직접 변경 | 두 후보를 함께 검사하고 마지막에 한 번 대입 |
| 높이 또는 폭이 1일 때 `s` 입력 | 한 축만 축소될 수 있음 | 어느 한 축이라도 최소값을 넘으면 전체 거부 |
| 순환 크기와 실제 크기가 섞임 | 상태 변경과 화면 분할 책임이 불명확 | 모델은 실제 크기만, 출력기는 시작·종료 좌표로 구간 계산 |
| 확대가 경계를 새로 넘음 | 크기 범위만 확인 | 넘는 축이 하나라도 있으면 전체 거부 |
| 보드 축소 후 도형 이탈 | 전체 도형 사전 검사 부족 | 모두 포함될 때만 보드 크기 반영 |
| 면적 직후 `q` 무시 | 정수 입력과 줄 입력 혼용 | 입력을 `getline`으로 통일 |
| 6번 좌표 범위 누락 | 문법과 값 검증의 역할 불명확 | 정점 `[-1,1]`, 텍스처 `[0,1]` 검사 |
| 다른 면의 같은 좌표도 중복 취급 | 중복 검사 범위가 파일 전체 | 현재 삼각형 안에서만 중복 거부 |
| 일부 면 오류에도 전체 성공 가능 | 유효 면 출력과 성공 판정 혼합 | 오류가 하나라도 있으면 전체 실패 |
| 6번 결과 저장 | 콘솔 출력만 존재 | 같은 보고서를 `outout-6/(입력파일이름-번호).txt`로 자동 저장 |

## 구조 개선

- `Application`의 `input_`, `output_`을 제거하고 `std::cin`, `std::cout`을 직접 사용합니다.
- `optional`, `span`, `string_view`, `from_chars`, 템플릿 공통 레코드를 제거했습니다.
- 문제 5는 명령 해석, 보드 상태, 화면 투영을 `BoardCommandParser`, `Board`, `BoardRenderer`로 나눴습니다.
- 문제 6은 문법 해석, 값 검증, 출력을 `MeshParser`, `MeshValidator`, `MeshReporter`로 나눴습니다.
- 상속이나 인터페이스 계층은 추가하지 않고 상태 없는 객체를 `Application`이 값으로 소유합니다.

## 애매한 부분

1. PDF의 y축 방향: 현재 `y` 증가는 화면 아래쪽입니다.
2. 접두사 없는 도형 명령: 기존 동작대로 1번을 대상으로 합니다.
3. 이미 순환 중인 도형의 확대: 순환 중인 축은 이미 양쪽 경계에 닿았으므로 확대를 차단합니다.
4. 오류 파일의 유효 면 표시: 전체는 실패시키되 진단을 위해 유효 면도 콘솔에 표시합니다.
5. 텍스처 없는 면: `f 1 2 3`과 `정점/텍스처` 형식을 모두 허용하며 한 면에서 혼용은 거부합니다.

## 검증 항목

- 높이 1의 `a` 반복, 너비 1의 `A`, `s`
- 가로·세로 경계의 `S`, `a`, `A` 전체 거부
- 한 축·두 축 이동 순환 뒤 `S` 반복 시 순환 축 확대 차단
- 음수 논리 좌표에서 보드 축소 거부
- 1,500회 결정적 상태 변경에서 실패 시 상태 불변
- 좌표 범위, 인덱스, 면 내부 중복, 공선 정점, 작은 유효 삼각형
- 일부 면만 잘못된 파일의 전체 실패와 오류 면 번호
- 문제 6 콘솔·출력 파일 내용 일치, 자동 번호 증가, 기존 파일 보존
- `data/err.txt`의 주요 파싱·검증 오류 10종 이상과 일부 유효 면 동시 보고

최신 소스는 MSVC x64 Debug 조건으로 빌드했습니다. C++ 회귀 테스트는 9,582개 단언과 1,500회의 결정적 보드 연산을 통과했고, 실제 `x64/Debug` 실행 파일 기반 CLI 검사 97개도 통과했습니다.
