# 30MB 이하 소스 프로젝트 배포

2026-11-03. 최종 ZIP과 같은 이름의 .SIZE.md/.manifest.json이 정확한 크기와 파일 목록을 기록한다.

기존 standard 작업 폴더 약405MiB 중 .vs가 약306MiB, x64 빌드 결과가 약83MiB였다. 기능 구현 자체가400MB인 것은 아니다. 프로젝트·C++·SDK·라이선스·문서·예제와 핵심 구조 그래프를 묶으며 IDE 캐시와 이전 빌드 산출물은 포함하지 않는다. 번들 SDK 안의 x64 라이브러리는 유지한다.

단일 프로젝트를 유지한다. 패키징 도구는 압축 전 합계와 ZIP 모두30,000,000바이트 미만이어야 성공으로 보고한다. 원본 .vs/x64/백업/사용자 파일은 삭제하지 않는다. 따라서 기존 작업 폴더의 전체 크기가 자동으로 줄어드는 것은 아니다.

ZIP은 새 C++ 소스 프로젝트다. 이전 standard.exe를 넣지 않으므로 사용자가 새 폴더에서 빌드한다. 기존 사용자 Framework.props/API 문서 수정도 현재 파일 그대로 포함하며, manifest는 그 SHA-256을 기록한다. Git 커밋만의 깨끗한 복제본과 구분한다.

저장소의 tools/Package-Standard.py는 재현 가능한 포함/제외 정책을 제공한다. 출력을 덮어쓰지 않으므로 다시 만들 때 새 --output 이름을 지정한다. 압축 파일 생성/크기 계산은 수행하지만 빌드·테스트·검증기·앱 실행·다른 PC 실행은 수행하지 않는다.

압축을 푼 standard.slnx 또는 standard.vcxproj를 사용한다. 사용자 빌드 후 examples/assembly와 docs/assembly가 실행 파일 폴더에 복사된다. Ctrl+F5로 기본 workspace를 읽고 [사용자 확인 절차](USER_CHECKS.md)를 수행한다.
