# 사용자 빌드·실행 확인 절차

2026-11-03. 에이전트는 빌드·테스트·검증기·앱 실행을 하지 않았다. 아래 항목은 사용자가 수행할 절차와 예상 결과다. 실패 시 명령, 콘솔 오류, 화면, 모드, Debug/Release를 함께 기록한다.

## 시작과 기존 모드 회귀

1. Visual Studio에서 standard 프로젝트를 x64/C++17로 빌드한다. main의 initialMode를 nullopt,0,1,9,22로 각각 지정한다. nullopt만 전환 키를 허용하며 기본 시작은1이다. -1/23은 컴파일 시 거부해야 한다.
2. nullopt의 0 키, 추가 실습에서 Alt+0, 대괄호0~22 순환을 확인한다. 추가 실습의 고유 숫자0은 해당 실습 기능이어야 한다. 고정0에서 Home은 기본 레시피를 복원한다.
3. [기존 모드 확인](../../USER_CHECKS.md)을 수행한다. 특히 공유 생성기를 바꾼 7번 격자,16/19번 탱크의 크기·색·입력·3뷰를 확인한다.

## 콘솔과 guide

- Enter를 누르지 않고 명령을 작성하는 동안 창의 애니메이션이 계속 진행하는지 확인한다. 한글 이름·공백 경로·따옴표·Backspace·Esc 줄 지우기를 확인한다.
- guide tank/truck/person, guide mount/normal/warp/face-track/cpp-effect/practice13~23을 실행한다. 실제 파일을 열어 표시한 줄과 함수가 맞는지 확인한다. 기능 이름과 같은 객체를 만들면 guide feature:normal처럼 구분한다.
- 소스가 없는 배포 폴더에서는 확인 불가능한 줄 번호를 추정하지 않아야 한다. 0에서 다른 모드로 나가면 콘솔 입력 모드가 복원돼야 한다.
- 창 최소화 중 명령은 복귀 뒤 처리되는 제한이 있다. 파이프/파일 표준 입력은 선택적으로 확인한다. 콘솔 quit와 창 Esc를 각각 확인한다.

## 패턴·계층·SRT

- tank/truck/person.assembly를 각각 load한다. 부품 클릭은 최상위 수작업 그룹을 선택하고, select <부품>은 해당 관절만 편집해야 한다.
- 부모의 이동·회전·배율·피벗이 모든 자식에 전달되는지 확인한다. 관절 중심과 자식 메시 중심이 다름을 확인한다. person의 팔다리는 반대 위상이어야 한다.
- 별도 장면에서 build tank/truck/person을 실행한다. C++ 트럭 문은 0~80° 및 -80~0°다. 수작업 레시피 문은 ±40° 왕복이다.
- pause on → seek <회전ID> 0 → center <그룹> keep 순서로 중심을 바꾼다. 기준 형상을 유지하는지 확인한다. 자전의 피벗과 부모 그룹 공전 중심을 따로 바꿔 본다.
- warp 그룹의 -1/1.5/1 배율과 그 아래 자식 회전을 확인한다. 반사 후 렌더 컬링과 클릭 피킹이 일치해야 한다. warp 그룹에 spin을 붙이면 안내와 함께 거부해야 한다.

## 면·노멀·부착 관절

- surface-lab.assembly를 load한다. 면4의 부착 부품은 면 회전과 함께 이동하며 자체 진자를 유지해야 한다. 창 전체 SRT와 3뷰에서도 같은 지점이어야 한다.
- surface <객체> <면>의 정점·삼각형 번호로 mount U/V를 바꾼다. U/V 음수, U+V>1, 없는 면·삼각형은 거부해야 한다. anchor의 XYZ는 원본 메시 좌표이며 표면 투영을 하지 않는다.
- normal flip/auto/XYZ를 바꾸면 조명이 달라져야 한다. 컬링 방향은 그대로여야 한다. winding flip은 컬링과 면 관절 +Z에 영향을 주며 조명 노멀은 별도다.
- face-srt의 배율·피벗, face-mode independent→부모 이동→hierarchy 복귀에서 전환 시 현재 자세 보존을 확인한다.
- 지연 face-track의 시간0/지연 직전/직후/종료를 seek로 확인한다. once/loop/pingpong과 play/enable/remove를 구분한다. 면 트랙을 remove하면 부착 전 행렬·가시성이 복원돼야 한다.
- triangle/triangle-add로 임의 메시를 만들고 vertex로 고친다. 중복점·일직선 삼각형·범위 밖 인덱스·0 노멀·0 배율은 거부해야 한다.

## 소유권·복원·물리

- 같은 이름/동작 ID, 같은 면의 다른 별칭, 경로+물리 등 중복 제어를 요청한다. 거부 뒤 Scene·카메라·렌더 설정이 이전 상태여야 한다.
- 물리 상자의 mesh 이동·면 변형, 물리 방 walls 이동, 벽을 보행 장애물로 등록, 보행 리그 자신의 부품을 장애물로 등록하는 요청은 거부해야 한다.
- 기본 장면에서 F로 바닥을 숨긴 뒤 G로 닫는다. 이미 이탈한 상자와 walker는 계속 떨어져야 한다. Home으로 초기화한다.
- box/sphere에 physics를 붙이고 body velocity/gravity/bounce를 변경한다. sphere 기본 탄성, box 기본 비탄성을 확인한다. release는 바닥 가시성을 바꾸지 않고 이탈시켜야 한다.
- drag <방> y .35로 오른쪽 버튼 드래그를 확인한다. 버튼을 누른 채 포커스를 잃어도 돌아왔을 때 계속 회전하지 않아야 한다. hold 키도 동일하게 확인한다.

## 사용자 C++ 입력 조립

CODE_GUIDE의 install-turn-key 예를 직접 편집·빌드해 H 키의 단일 회전과 enable/remove를 확인한다. Input 콜백에서 clear/load/remove 후 이전 목록의 다른 훅이 실행되지 않는지 확인한다. 사용자 마우스/커서 상태는 focus(false)에서 해제한다. callback 예외에서 앱 전체를 종료하지 않고 기본 입력을 해제하고 정지하는지도 확인한다. 이 예제는 사용자가 추가할 코드이며 기본 콘솔 명령에 이미 등록된 기능은 아니다.

## 저장·경로·오류

- warp,면 관절,면 트랙,normal/cull,drag,카메라,3뷰를 포함한 장면을 save→clear→load한다. 기준 배치와 설정이 복원돼야 한다. 진행 중인 프레임·순간 jump/release·사용자 콜백 내부 상태의 정확한 복원은 검사 대상이 아니다.
- LF와 CRLF로 저장한 파일에서 save/load를 반복한다. # @state-begin 이후 기준값 블록이 작성 레시피에 누적돼 파일이 계속 커지지 않아야 한다. 잠긴 물리 메시의 같은 rest 값은 불러오기를 막지 않아야 한다.
- 잘못된 레시피의 중간 줄을 load하고 이전 장면이 복원되는지 확인한다. 저장 실패 시 기존 파일이 보존돼야 한다. 외부 IO나 사용자 콜백의 외부 부수효과는 CPU Scene 복원 범위 밖이다.
- 사용자 빌드 뒤 출력 폴더 examples/assembly와 docs/assembly를 확인한다. 다른 현재 작업 폴더에서 load examples/assembly/tank.assembly를 실행하면 실행 파일 폴더의 파일을 찾는지 확인한다.
