# C++26 리플렉션과 현재 핫로드 설계

2026-11-03. 프로젝트 설정은 C++17이다. 빌드·컴파일러 기능 테스트는 하지 않았다.

## 확인한 표준 기능

C++26 Reflection for C++26의 std::meta::info와 이를 포함하는 타입은 consteval-only다. 컴파일 타임에 선언/타입/멤버/이름/소스 위치를 조사하고 코드를 생성하는 기능이며 info 자체가 런타임으로 전달되는 방식은 아니다. 런타임에 일반 C++ 소스 텍스트를 읽어 새 클래스·함수를 실행 코드로 바꾸는 기능도 아니다. [WG21 P2996R13 §4.3.3](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2025/p2996r13.html#consteval-only)

다만 컴파일 타임에 얻은 이름·멤버 접근·함수 포인터 등을 **일반 구조체/함수 표**로 생성해 런타임 편집기에 사용할 수 있다. 값 편집·직렬화·명령 등록을 자동화하는 데 유용하다. §3.7/3.11 명령줄 옵션 예가 이 구분을 보여 준다. [공식 제안 예제](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2025/p2996r13.html)

MSVC의 구현 범위는 설치된 버전과 해당 기능을 별도로 확인해야 한다. 이 작업은 `/std:c++26` 전환이나 별도 컴파일러 설치를 수행하지 않았다. [Microsoft 언어 지원표](https://learn.microsoft.com/en-us/cpp/overview/visual-cpp-language-conformance)

## 이번에 적용한 것

- GuideRecipes.h/.cpp: 명시적 C++17 메타데이터. 기능/목표/변경 예/제약/디버깅/예상 결과/소스 표식을 등록한다.
- AssemblyGuide.cpp: 디스크의 현재 소스를 읽어 실제 줄과 주변 코드를 출력한다. 컴파일 시점의 고정 줄 번호를 그대로 신뢰하지 않는다.
- diagnose: 알려진 런타임 Node/Behavior/Feature 값과 부모·행렬·표시 상태를 출력한다. 임의 지역변수는 디버거로 본다.
- Ctrl+F5: 외부 .assembly를 재로드한다. 실패 시 조립 상태를 보존한다.
- C++ 기능 구현 변경: 사용자가 재빌드하고 실행한다. 동적 라이브러리/JIT/바이너리 패치 시스템은 추가하지 않았다.

즉 별도 reflection 실행 프로젝트를 만들기 전에 필요한 편집 안내를 현재 프로젝트의 독립 메타데이터 모듈로 제공했다. 이후 지원 컴파일러를 채택하면 가이드/프로퍼티 테이블의 생성 부분을 C++26으로 바꿀 수 있다. 알고리즘 변경 이유와 디버깅 절차는 리플렉션이 자동으로 알아내는 정보가 아니므로 사람이 등록한 가이드를 유지해야 한다.

## 변경 종류와 반영 방법

| 변경 | 반영 |
|---|---|
| 외부 레시피의 위치·크기·연결·기능 선택 | Ctrl+F5 / reload |
| 콘솔 입력으로 현재 기준값 변경 | 현재 Scene에 즉시 적용 |
| C++ 숫자·조건·함수·새 클래스 | 사용자 재빌드/재실행 |
| 가이드의 코드 예·표식 메타데이터 | 사용자 재빌드 |
| 편집 뒤 달라진 소스 줄 위치 | guide 실행 시 현재 파일을 다시 검색 |
| private 원본 실습의 런타임 변수 | 원본 함수 중단점/Watch 또는 명시적 DTO/가이드 추가 |

리플렉션, 런타임 메타데이터, 설정 핫로드, 실행 코드 핫리로드를 구분한다. 현재 사용자에게 제공한 것은 메타데이터/진단/설정 핫로드이며, C++26 런타임 코드 교체를 구현했다고 보고하지 않는다.
