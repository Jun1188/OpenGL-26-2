시험 현장 구현 순서: 육면체·렌더링·계층 변환

공통 구현·전체 API 사례응용패턴·그네 통합

중간고사: 육면체로 렌더링과 변환을 추적하기

사용자가 전달한 시험 조건: 코딩테스트에서 육면체를 사용한다. 바인딩·M/V/P·계층·면 변환을 바꾸는 문제는 대비용 예상 사례다. 실제 출제 범위·제한 시간·허용 자료가 확정되었다는 뜻은 아니다.

같은 육면체에서도 정점 연결, 전체 자세, 카메라, 투영, 부모 관계, 한 면의 자세를 각각 바꿀 수 있다. 먼저 문제의 동사를 아래 표에 대응한다. 그다음 해당 상태를 만드는 함수와 그 상태를 읽는 렌더링 단계를 찾는다.

프레임 루프바인딩M·SRT·피벗VP계층·레이어면 열기클립 이후·법선현장 구현 순서
문제의 요구바꿀 상태주요 위치
면 연결·색·정점 형상을 바꾼다CPU 메시, 정점 속성, 인덱스, GPU 업로드Scene의 메시 API → Renderer::upload
상자 전체를 이동·회전·확대한다Transform3D → MScene::setTransform → worldMatrix
카메라를 돌린다Camera.position/target/up → VCameraSystem::viewMatrix
원근감·시야·화면 비율을 바꾼다Camera의 투영 값·aspect → PCameraSystem::projectionMatrix
다른 상자를 따라 회전하거나 한 면을 연다부모 관계·모션 레이어·면 피벗setParent / bindEntity / setFaceLocalMatrix
CPU: 메시·입력·시간 → 엔티티/면 M, 카메라 V, 투영 P
GL 상태: 프로그램 + VAO/EBO + uniform + 텍스처 + 깊이/컬링
정점: local → M → world → V → view → P → clip
고정 처리: 프리미티브 조립 → 클리핑 → w로 나눔 → NDC → viewport
화면: 래스터화·보간 → 프래그먼트 셰이더 → 깊이/블렌딩 → framebuffer

이 순서는 개념상 데이터 흐름이다. GPU는 일부 프래그먼트 검사를 앞당길 수 있다. 바인딩은 좌표를 변환하는 행렬 단계가 아니라, 뒤의 GL 명령이 사용할 대상과 상태를 선택하는 CPU 측 작업이다.

프레임 반복과 콜백 실행 시점

화살표가 조건 검사로 돌아가면 다음 프레임이다. 최소화 상태는 WaitEvents 뒤 시간 기준을 재설정한다. 입력·update 뒤의 종료 요청은 반복을 중단한다. 모션·컨텍스트·렌더·swap 실패와 콜백 예외도 shutdown 경로로 간다. update는 프레임당 한 번이며 여러 카메라 렌더 패스에서 반복하지 않는다.

8. 시험 현장 구현 순서: 한 상자로 단계를 분리한다

  1. 요구를 단계로 나눈다. 입력, 전체 M, 부모·자식, 면, V, P, 렌더 상태 중 무엇을 바꿀지 정한다. 지정하지 않은 단계는 기준값으로 둔다.
  2. 정지한 단위 상자를 만든다. addCuboid({1,1,1},{0,0,0})의 ID를 보관하고 카메라·depthTest를 설정한다. optional/bool 결과를 처리한다.
  3. M부터 구현한다. 0°→90°의 중심과 정점 하나를 종이에서 예측한다. basis·localBasis와 행렬 곱의 좌우를 정한다.
  4. 필요한 계층을 추가한다. 공전 중심은 addGroup, 부품 추종은 setParent, 한 면 열기는 면 API를 사용한다. 레이어를 사용하면 anchor와 parent/local의 합성 위치도 정한다.
  5. 입력과 시간을 분리한다. 키는 선택·목표 각도·재생 상태를 바꾸고 update에서 dt로 각도를 한 번만 진행한다. 기준 자세에서 계산하며 같은 회전을 불필요하게 누적하지 않는다.
  6. V와 P를 따로 바꾼다. 카메라 공전은 position/target, 투영은 orthographic/FOV/aspect에 연결한다. 창과 각 뷰의 크기 변경도 처리한다.
  7. 그리기 직전의 의존 관계를 추적한다. program→VAO/EBO→MVP/법선/텍스처→DrawElements를 확인한다. Console의 일반 그리기 호출과 Renderer 내부의 책임을 구분한다.
  8. 사용자가 빌드·실행한다. 초기화, 정지/재개, 90°, 면의 뒤쪽, 가로/세로 화면, 부모만/자식만 조작을 순서대로 확인한다.

입력·갱신을 연결하는 독립 main

Framework.h와 현재 Framework.props를 사용하는 프로젝트용 새 예제다. 기존 main과 동시에 등록하지 않는다. Space는 자전 정지/재개, O는 원근/직교 전환, R은 각도를 0으로 복원한다. 화면 출력은 확인하지 않았으며 실행 확인은 사용자가 한다.

#include "framework/Framework.h"

int main() {
    graphics::Application app;
    std::optional<graphics::EntityId> cube;
    float degrees = 0;
    bool playing = true;
    app.setInitHandler([&](graphics::Application& current) {
        cube = current.getScene().addCuboid({1,1,1}, {0,0,0});
        auto& camera = current.getCamera();
        camera.position = {3,2,5}; camera.target = {0,0,0};
        camera.orthographicHalfExtent = 2;
        current.getRenderOptions().depthTest = true;
        return cube.has_value();
    });
    app.setKeyHandler([&](graphics::Application& current, int key, int action) {
        if (action != GLFW_PRESS) return;
        if (key == GLFW_KEY_SPACE) playing = !playing;
        if (key == GLFW_KEY_R) degrees = 0;
        if (key == GLFW_KEY_O) {
            auto& camera = current.getCamera();
            camera.orthographic = !camera.orthographic;
        }
        if (key == GLFW_KEY_ESCAPE) current.requestClose();
    });
    app.setUpdateHandler([&](graphics::Application& current, float dt) {
        if (playing) degrees = std::fmod(degrees + 45.0f * dt, 360.0f);
        graphics::Transform3D t;
        t.rotation = glm::mat3(glm::rotate(glm::mat4(1), glm::radians(degrees),
                                         glm::vec3(0,1,0)));
        if (!cube || !current.getScene().setTransform(*cube, t)) current.requestClose();
    });
    return app.run();
}

app은 창과 루프의 소유자, cube는 Scene 안의 상자를 찾는 ID, degrees와 playing은 응용 상태다. setUpdateHandler에서는 자세만 갱신한다. 일반 렌더링은 Application에 맡기므로 여기서 GL 바인딩을 다시 작성하지 않는다. Application이 갱신하는 MotionSystem을 중복 update하지 않는다.

사용자 확인예상 결과·되돌아갈 위치
예제 실행, Space→Space상자가 Y축으로 자전하고 정지/재개한다. 정지하지 않으면 시간 갱신과 입력 상태를 확인한다.
정지한 뒤 R다음 update에서 0° 자세다. 복원되지 않으면 Scene을 덮어쓰는 다른 모션을 확인한다.
O, 별도 시도로 카메라 Z=5→10원근에서는 상자가 작아지고 직교에서는 크기가 같다. V와 P의 역할을 확인한다.
가로·세로로 창 크기 변경상자의 비율을 유지한다. 늘어나 보이면 viewport와 aspect를 확인한다.
부모 90°·자식 X=2, 다른 시도로 자식만 90°부모 조작은 중심도 이동한다. 자식만 조작하면 제자리에서 회전한다.
뚜껑 0°→90°한 모서리가 고정되고 해당 면만 열린다. 상자 전체가 움직이면 수정 대상, 축이 어긋나면 피벗 좌표를 확인한다.

이 표는 미실시 확인 절차이며 통과 결과가 아니다. 회상 과제: 중심 X=2인 상자의 “제자리 회전”과 “원점 주위 공전”에서 T와 R 중 무엇을 왼쪽에 두는지 설명한다.

바인딩·M/V/P·전체 변환 설명

추가 응용: 기존 그네·사람형 구현 순서

아래 착석·관절 예제는 추가 응용 자료다. 육면체 코딩테스트의 확정 요구사항이 아니다.

기존 시험 순서 문서는 저장소 docs/code-guide/exam.html에 존재한다. 이 문서는 그 순서를 현재 standard의 착석·관절 SRT 조작까지 연결해 독립 폴더 안에서 읽을 수 있도록 정리한 최신판이다. 시험의 실제 제한 시간과 허용 자료는 문제 지시를 따른다.

1. 요구사항을 상태와 함수로 바꾸기

사람이 앉는다, 그네가 흔들린다, 관절을 선택한다, 세 뷰로 본다 같은 동사를 적는다. 각 동사를 좌석 부모 관계, hinge 모션, 선택 인덱스, RenderPass에 연결한다. 출력 조건과 입력 키를 먼저 표로 만든다.

2. 프로젝트·main 골격 준비

standard.sln, x64, Framework.h 포함을 확인한다. main은 Application과 응용 상태를 만들고 init/update/key/render 콜백을 저장한 뒤 run을 한 번 호출한다. 예제 main을 여러 개 프로젝트에 등록하지 않는다.

3. 정적 장면부터 조립

바닥·고정 프레임·좌석·앉은 사람을 먼저 만든다. 부모는 frame→hinge→seat→person.root이며 지지대는 frame의 자식이다. 관절 위치·바라보는 +Z 방향·착석 높이를 애니메이션 없이 확인할 준비를 한다.

4. 각 관절 기준 SRT·피벗 결정

HumanoidPose::seated로 엉덩이·무릎을 굽힌 뒤 createJointAnimation으로 rest를 캡처한다. basis는 부모 공간 위치, localBasis는 모델 피벗이다. 관절 선택 목록은 EntityId 또는 트랙 인덱스를 보관하고 포인터는 보관하지 않는다.

5. 입력 명령 연결

PRESS에서 모드·선택 관절·축을 바꾼다. 방향키·PageUp/Down·+/-는 선택 트랙의 rest만 수정한다. Space는 시간을 정지하고 R은 선택 rest를 복원한다. 애니메이션 함수와 입력이 같은 Scene 변환을 덮어쓰지 않게 한다.

6. 누적 시간과 모션 추가

AnimationClock.advance(dt)로 seconds를 누적하고 poseHierarchy(scene,animation,seconds)를 호출한다. dt를 누적 절대 시간 대신 넘기지 않는다. 선형보간은 편도 시간·재생 방식, 진자는 진폭·주기를 지정한다. Application이 자동 진행하는 MotionSystem을 따로 중복 update하지 않는다.

7. 충돌·추가 패턴은 필요한 경우만 결합

걷기·점프가 요구되면 CharacterBody 상태→stepCharacter→표시 관절 순서로 넣는다. 좌석에 앉은 사람에게 바닥 보행 상태를 그대로 적용하지 않는다. 벽 표시 개방과 실제 충돌 통과를 구분한다.

8. 렌더링·다중 뷰·피킹 연결

기본 renderScene 또는 사용자 renderViews를 택한다. update는 프레임당 한 번, 렌더는 여러 카메라로 반복한다. framebuffer의 크기·viewport 원점·DPI 좌표를 맞춘다.

9. 복원·오류·종료 처리

각 optional/bool 결과를 확인한다. 중복 관절 트랙·0 주기·비균일 rest 배율은 거부한다. 초기화에서 모든 ID·모드·시계를 다시 구성한다. 종료는 requestClose를 사용하고 GPU 해제를 컨텍스트 수명 안에서 처리한다.

10. 사용자가 최종 실행 확인

사용자가 빌드·실행한다. 그네를 멈추고 엉덩이·무릎 착석, 선택 팔꿈치의 자식 전달, hinge의 전체 전달, 지지대 고정, 피벗 이동 후 회전 중심, Space 재개 뒤 편집 유지, 리셋, 세 뷰 일치를 확인한다. 이 작성 작업에서는 실행하지 않았다.

착석·관절 구현 출발 코드

struct SwingExample {
    graphics::AnimationClock clock;
    std::vector<graphics::JointAnimation> animation;
    bool initialize(graphics::Scene& scene) {
        graphics::HumanoidConfig personConfig;
        personConfig.grid.frame=glm::translate(glm::mat4(1),glm::vec3(-2,0,0));
        auto person=graphics::AnimationSystem::addHumanoid(scene,personConfig); if(!person) return false;
        auto pose=graphics::HumanoidPose::seated();
        if(!graphics::AnimationSystem::poseHumanoid(scene,*person,pose)) return false;
        graphics::SwingConfig config;config.pivot={1,3,0};config.pendulum.periodSeconds=3;
        auto swing=graphics::AnimationSystem::addSwingWithRider(scene,config); if(!swing) return false;
        animation=swing->animation;
        graphics::PendulumMotion elbow;elbow.amplitudeDegrees=10;
        graphics::Motion motion;if(!motion.append(graphics::Motion::pendulum(elbow))) return false;
        auto track=graphics::AnimationSystem::createJointAnimation(scene,swing->person.elbows[0],motion);
        if(!track) return false;
        animation.push_back(*track);clock.reset();return true;
    }
    bool update(graphics::Scene& scene,float dt) {
        return clock.advance(dt)&&graphics::AnimationSystem::poseHierarchy(scene,animation,clock.seconds);
    }
};

실제 main 연결

#include "Console.h"

/// 콜백을 등록하고 애플리케이션을 실행한다.
int main() {
    graphics::Application app;
    Console sample(app);

    app.setInitHandler([&](graphics::Application&) {
        return sample.initScene();
    });
    app.setKeyHandler([&](graphics::Application&, int key, int action) {
        sample.onKey(key, action);
    });
    app.setMouseHandler([&](graphics::Application&, const graphics::MouseEvent& event) {
        sample.onMouse(event);
    });
    app.setUpdateHandler([&](graphics::Application&,float dt) {sample.onUpdate(dt);});
    app.setRenderHandler([&](graphics::Application&) {return sample.onRender();});

    graphics::ApplicationConfig config;
    config.title = "standard - Motion, Grid, diagnostics and render passes";
    return app.run(config);
}
