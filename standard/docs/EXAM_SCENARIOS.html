시험 시나리오 튜토리얼

실습을 바탕으로 한 무작위 코딩 문제가 나왔을 때, 0번 기능 조립 모드로 원하는 기능을 빠르게 만들고 그 구성으로 시작 모드를 확정하는 방법입니다. 아래 시나리오는 모두 examples/assembly/scenarios/에 실제 레시피 파일로 들어 있어 바로 불러올 수 있습니다.

창 두 개를 구분하세요. 명령은 검은 콘솔 창의 asm>에 입력하고 Enter를 누릅니다. 키 조작은 OpenGL 창을 클릭해 포커스를 준 뒤 누릅니다. 키가 안 먹으면 대부분 포커스가 콘솔에 있는 경우입니다.

준비

  1. Visual Studio에서 standard.sln을 열고 x64 Debug로 빌드·실행합니다.
  2. OpenGL 창에서 Alt+0을 누르면 0번 조립 모드로 들어갑니다. 기본 장면(사람·그네·탱크·방)이 나타납니다.
  3. 콘솔에 help를 입력하면 명령 목록이, guide 기능이름을 입력하면 그 기능을 고칠 C++ 파일과 줄 번호가 나옵니다.

기본 흐름

  1. 문제와 가장 가까운 시나리오 고르기

    아래 시나리오 목록에서 요구와 비슷한 것을 고릅니다. 실습 번호로 찾으면 빠릅니다. 기존 실습과 거의 같다면 0번을 쓰지 않고 방법 C로 그 실습을 고정하는 편이 더 빠릅니다.

  2. 불러와서 화면으로 확인

    load "examples/assembly/scenarios/s06-tank.assembly"

    불러오기에 실패하면 이전 장면이 그대로 남고, 콘솔에 실패한 줄과 이유가 나옵니다.

  3. 콘솔 명령으로 문제에 맞게 변형

    숫자(위치·속도·각도)를 바꾸거나 객체·동작·키를 더합니다. 명령은 바로 적용되므로 화면을 보며 맞춥니다. 잘못 넣은 동작은 remove 동작ID, 키는 unbind 키로 지웁니다.

    linear swapA left 4 1 0 2 pingpong
bind SPACE press "pause on"
camera pose 0 5 9 0 1 0 0 1 0

  4. 저장

    save "examples/assembly/exam.assembly"

    저장 파일에는 입력한 명령과 현재 편집값이 들어갑니다. 저장 위치의 절대 경로가 콘솔에 나옵니다. 애니메이션의 현재 시각이나 물리 속도는 저장되지 않으므로, 다시 불러오면 처음 상태부터 다시 시작합니다.

    저장 위치를 확인하세요. save의 상대 경로는 실행할 때의 작업 폴더를 기준으로 합니다.

    • Visual Studio에서 F5로 실행하면 작업 폴더가 standard/입니다. 파일이 소스 폴더에 저장되므로 x64를 지워도 안전합니다.
    • x64\Debug\standard.exe를 더블클릭해 실행하면 작업 폴더가 x64\Debug입니다. 이때 저장한 파일은 x64\Debug\examples\...에 생기므로 x64를 지우면 함께 사라집니다. 다시 빌드할 때도 소스 쪽 파일로 덮어써질 수 있습니다.
    • exe를 직접 실행했다면 절대 경로로 저장합니다. 예: save "C:/Users/User/Desktop/Git/GitHub/OpenGL-26-2/standard/examples/assembly/exam.assembly"

    저장한 뒤 콘솔에 출력된 경로가 \x64\가 아닌 소스 폴더인지 확인하세요.

  5. 모드 확정

    프로그램을 켜자마자 그 장면으로 시작하게 만듭니다. 모드 확정의 방법 A~C 중 하나를 고릅니다.

시나리오

각 카드의 복사 버튼은 콘솔에 붙여 넣을 load 명령을 복사합니다. 레시피 보기를 펼치면 파일 전체가 보입니다. 카드 내용은 레시피 파일의 # @ 머리말에서 자동으로 만들어집니다.

    시나리오 데이터(viewer/scenarios.js)를 읽지 못했습니다. 저장소에서 python tools/Update-StandardDocs.py를 실행하세요.

    자주 쓰는 명령 요약

    요구명령주의
    계층 객체group · part box 부모 이름 위치3 크기3 · joint · parentjoint 위치가 회전 중심이 된다.
    자전 / 공전spin ID 대상 축 도/초 · orbit ID 대상 축 도/초 중심3공전은 부모 그룹에 걸고 자전은 자식에 건다.
    이동 동작linear ID 대상 DX DY DZ 초 pingpong · path ID 대상 1~6 초 · pendulum한 대상의 위치는 동작 하나만 소유한다.
    면 동작face ID 대상 면 hinge 모서리 도/초 · face-track ... turn/move/scale면 번호는 surface 대상 all로 확인한다.
    면 표시·색visible 대상 면 on/off · facecolor 대상 면 R G B · cull 대상 all none안쪽 면을 보려면 컬링을 끈다.
    키 입력bind 키 press "명령" · bind 키 hold "move/rotate ..."숫자 키는 bind할 수 없다. hold는 값에 dt를 곱한다.
    재생 제어play ID on/off · enable ID on/off · seek ID 초 · pause on/offplay off는 현재 자세를 유지하고, enable off는 기여를 없앤다.
    카메라camera pose/orbit/zoom/move/projection · view 1/3창에는 기본 카메라 키가 없으므로 bind로 연결한다.
    물리·보행add room · physics · walk · jump · visible 방 5 off교육용 AABB 모델이다. 정밀 충돌이 아니다.
    기존 실습 재사용feature add 이름 1~22 · feature focus 이름 · feature parts 이름입력은 focus된 기능에만 전달된다.

    전체 문법은 0번 명세(SPEC.md)에 있습니다.

    모드 확정

    방법 A · 레시피 파일로 확정 (재빌드 없음)

    시험 중 가장 빠른 방법입니다. 저장한 파일을 불러오면, 그 다음부터는 Ctrl+F5가 그 파일을 다시 읽습니다. 레시피 파일을 메모장으로 고친 뒤 Ctrl+F5를 누르면 바로 반영됩니다.

    load "examples/assembly/exam.assembly"

    Ctrl+F5는 모드를 고정한 상태에서도 0번 작업공간으로 들어갑니다. 처음 들어갈 때 읽는 파일은 examples/assembly/workspace.assembly이므로, 이 파일 내용을 내 레시피로 바꿔 두어도 됩니다.

    방법 B · 실행하자마자 0번 + 내 장면 (재빌드 필요)

    1. main.cpp의 시작 모드를 0으로 고정합니다. 
      constexpr std::optional<int> initialMode = 0;
    2. modes/Mode0Recipe.cpp의 USER_RECIPE_BEGIN~USER_RECIPE_END 배열을 내 레시피로 바꿉니다. 둘 중 하나를 고릅니다. 
      // 1) 파일을 불러오는 한 줄만 둔다
const char* commands[] = {
    "load \"examples/assembly/exam.assembly\""
};

// 2) 파일 없이 명령을 직접 넣는다 (제출할 때 파일이 따로 필요 없음)
const char* commands[] = {
    "add box cube 0 1 0 2 2 2",
    "face lid cube 4 hinge 0 45",
    "bind T press \"play lid off\""
};
    3. 다시 빌드하고 실행합니다. 바로 그 장면으로 시작하며, Home을 누르면 이 레시피로 다시 만들어집니다.

    레시피 안의 따옴표는 C++ 문자열 안이므로 \"로 씁니다. 파일 경로는 실행할 때의 작업 폴더를 먼저 찾고, 없으면 실행 파일 폴더에서 찾습니다. examples/assembly/ 아래 파일은 빌드할 때 실행 파일 폴더로 복사됩니다.

    방법 C · 기존 실습 모드를 그대로 고정 (재빌드 필요)

    명령으로 안 될 때 C++로 확장

    난수, 조건 분기, "세 번 누르면 다음 단계" 같은 상태 전이는 명령만으로 만들 수 없습니다. 새 명령을 C++로 추가하고, 그 명령을 레시피에 한 줄 넣습니다.

    1. modes/AssemblyExtensions.cpp의 USER_COMMAND_BEGIN 안에 분기를 추가합니다. 
      if (args[0] == "my-arm") {
    require(args.size() == 2, "my-arm <이름>");
    const auto& name = args[1];
    scene.group(name, {0, 0, 0});
    const auto shoulder = scene.part("joint", name, "shoulder", {0, 1, 0});
    scene.part("box", shoulder, "arm", {0, -.3f, 0}, {.2f, .6f, .2f});
    graphics::PendulumMotion sway;
    sway.axis.direction = {0, 0, 1};
    sway.amplitudeDegrees = 30;
    sway.periodSeconds = 2;
    Behavior motor;
    motor.name = name + ".motor";
    motor.target = shoulder;
    require(motor.motion.append(graphics::Motion::pendulum(sway)), "arm motor");
    scene.attach(std::move(motor));
    return true;
}
    2. 다시 빌드한 뒤 콘솔에서 my-arm robot을 실행해 확인합니다.
    3. 잘 되면 레시피(방법 A 또는 B)에 my-arm robot 한 줄을 넣어 확정합니다.

    프레임마다 도는 동작은 Effect::Custom, 키·마우스 반응은 Effect::Input을 씁니다. 예제와 규칙은 CODE_GUIDE.md에 있습니다. 명령이 실패하면 C++ 안에서 만든 부분까지 포함해 이전 장면으로 되돌아갑니다.

    막힐 때

    증상원인과 해결
    키를 눌러도 반응이 없다OpenGL 창을 클릭해 포커스를 준다. 숫자패드 방향키(NumLock 꺼짐)는 인식되지 않으므로 독립 방향키를 쓴다.
    bind 1 ...이 거부된다숫자·F키·대괄호·Esc·Home은 모드 전환 키라서 bind할 수 없다. 영문자나 방향키를 쓴다.
    동작을 붙이면 "소유" 오류가 난다한 대상의 위치를 path·orbit·linear·물리가 동시에 가질 수 없다. 부모 그룹(공전)과 자식 그룹(이동)으로 나눈다. 같은 면도 동작 하나만 가진다.
    "중복" 오류가 난다같은 이름의 객체·동작·키가 이미 있다. clear로 비우거나 remove · unbind 후 다시 만든다.
    회전 중심이 이상하다pivot 대상 center keep으로 중심을 맞추거나, 회전 중심 자리에 joint를 두고 그 아래에 부품을 붙인다.
    면 번호를 모르겠다surface 대상 all이 면별 정점과 삼각형을 출력한다. 육면체는 0 앞, 1 뒤, 2 왼쪽, 3 오른쪽, 4 위, 5 아래다.
    바닥을 닫았는데 공이 안 돌아온다이미 빠진 객체는 돌아오지 않는 것이 정상이다. Ctrl+F5나 load로 다시 만든다.
    저장한 레시피가 사라졌다exe를 직접 실행해 x64\Debug에 저장한 뒤 x64를 지웠거나 다시 빌드한 경우다. 소스 폴더(standard/examples/assembly/)에 저장하고, 저장 후 출력된 경로를 확인한다.
    C++를 고쳤는데 그대로다Ctrl+F5는 레시피만 다시 읽는다. C++ 변경은 Visual Studio에서 다시 빌드해야 반영된다.
