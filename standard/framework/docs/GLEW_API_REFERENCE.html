1. 역할과 현재 구현

GLEW는 OpenGL 함수 진입점과 기능 지원 정보를 제공한다. 창과 컨텍스트는 GLFW가 만들고, 행렬은 GLM이 계산한다. glBindBuffer·glDrawElements는 OpenGL API이며 GLEW 자체 API와 구분한다.

현재 프로젝트의 경로: Native.h: GlfwApi / GlApi / Module는 GLEW 헤더에서 GL 타입과 PFNGL…PROC 타입을 가져온다. OpenGL 함수 주소는 GlApi::load() → wglGetProcAddress → 필요 시 opengl32.dll의 GetProcAddress로 구한다. 이 경로에는 glewInit() 호출과 GLEW DLL 로딩이 없다. 아래 GLEW 초기화 예제는 일반적인 사용법이다.
주체책임소유·수명
GLFW창·OpenGL 컨텍스트·입력Application이 창 핸들과 GLFW 종료를 관리한다.
현재 GlApiOpenGL 함수 주소 해석Module이 opengl32.dll 모듈 핸들을 관리한다. 함수 포인터는 GL 객체 소유권이 아니다.
GLEW 일반 사용glewInit 후 함수 진입점 사용컨텍스트가 current인 상태에서 초기화한다. 별도 glewTerminate 함수는 없다.
Renderer셰이더·VAO·버퍼·텍스처컨텍스트를 없애기 전에 GL 자원을 삭제한다.

2. 두 초기화 경로

일반 GLEW 사용:

glfwInit → glfwCreateWindow → glfwMakeContextCurrent → glewInit → 지원 기능 확인 → OpenGL 호출

현재 소스:

Application::initialize → GLFW 창 생성 → ensureContext → Renderer::initialize → GlApi::load → Renderer의 GL 함수 호출

3. 핵심 API 명세

G01

glewInit

GLenum glewInit(void);
인자
없음. 현재 스레드의 GL 컨텍스트를 사용한다.
반환
GLEW_OK이면 성공. 나머지는 GLEW 오류 코드.
조건·주의
유효한 컨텍스트를 current로 만든 뒤 호출한다. 실패하면 최신 GL 함수 사용을 중단한다.
현재 사용
현재 경로에서는 호출하지 않는다. Renderer::initialize는 GlApi::load를 사용한다.
근거
동봉 GL/glew.h · 공식 문서
GLenum status = glewInit();
if (status != GLEW_OK) { /* 오류 처리 후 종료 */ }
G02

glewGetErrorString

const GLubyte* glewGetErrorString(GLenum error);
인자
error: glewInit 등에서 받은 GLEW 오류 코드.
반환
오류 설명 문자열을 가리키는 포인터.
조건·주의
반환 문자열을 해제하거나 수정하지 않는다. OpenGL glGetError 코드 해석용 함수가 아니다.
현재 사용
현재 경로에서는 호출하지 않는다. 프로젝트 진단은 Diagnostics를 사용한다.
근거
동봉 GL/glew.h · 공식 문서
const auto* text = glewGetErrorString(status);
G03

glewGetString

const GLubyte* glewGetString(GLenum name);
인자
name: GLEW_VERSION 등의 조회 항목.
반환
GLEW 정보 문자열 포인터. 잘못된 항목은 null.
조건·주의
GLEW_VERSION은 GLEW 버전이다. 드라이버 OpenGL 버전은 glGetString(GL_VERSION)으로 따로 조회한다.
현재 사용
현재 경로에서는 호출하지 않는다. 동봉 디렉터리 표기는 glew-2.3.1이다.
근거
동봉 GL/glew.h · 공식 문서
const auto* version = glewGetString(GLEW_VERSION);
G04

glewIsSupported

GLboolean glewIsSupported(const char* name);
인자
name: 공백으로 구분한 GL_VERSION_x_y 또는 GL_확장 이름.
반환
요구한 기능을 모두 지원하면 GL_TRUE, 아니면 GL_FALSE.
조건·주의
glewInit 성공 후 조회한다. 지원 여부와 셰이더 컴파일 성공은 별도 조건이다.
현재 사용
현재 경로에서는 호출하지 않는다. 필요한 주소를 GlApi에서 해석한다.
근거
동봉 GL/glew.h · 공식 문서
if (!glewIsSupported("GL_VERSION_3_3")) { /* 기능 부족 */ }
G05

glewExperimental / GLEW_VERSION_3_3

extern GLboolean glewExperimental;
// GLEW_VERSION_3_3: 지원 여부를 읽는 매크로
인자
glewExperimental: 초기화 동작을 조정하는 전역 변수.
반환
함수가 아니다. GLEW_VERSION_3_3은 초기화 후 지원 여부를 읽는다.
조건·주의
필요 시 glewInit 전에 glewExperimental = GL_TRUE를 설정한다. 이것이 드라이버에 없는 기능을 추가하지는 않는다.
현재 사용
현재 GlApi 경로에는 영향을 주지 않는다.
근거
동봉 GL/glew.h · 공식 문서
glewExperimental = GL_TRUE;
GLenum status = glewInit();
if (status == GLEW_OK && GLEW_VERSION_3_3) { /* 사용 */ }

4. 일반 GLEW 초기화 예제

기존 프레임워크의 로더와 별개인 독립 예제이다. GLEW·GLFW의 헤더·링크 설정이 된 환경을 전제로 한다.

#include <GL/glew.h>
#define GLFW_INCLUDE_NONE
#include <GLFW/glfw3.h>
#include <iostream>

int main() {
    if (!glfwInit()) return 1;
    glfwWindowHint(GLFW_CONTEXT_VERSION_MAJOR, 3);
    glfwWindowHint(GLFW_CONTEXT_VERSION_MINOR, 3);
    glfwWindowHint(GLFW_OPENGL_PROFILE, GLFW_OPENGL_CORE_PROFILE);
    GLFWwindow* window = glfwCreateWindow(800, 600, "GLEW example", nullptr, nullptr);
    if (!window) { glfwTerminate(); return 1; }
    glfwMakeContextCurrent(window);
    glewExperimental = GL_TRUE;
    const GLenum status = glewInit();
    if (status != GLEW_OK) {
        std::cerr << reinterpret_cast<const char*>(glewGetErrorString(status)) << '\n';
        glfwDestroyWindow(window);
        glfwTerminate();
        return 1;
    }
    // 필요한 GL 자원을 만들고 사용한다.
    // GL 자원을 먼저 해제한 뒤 창을 제거한다.
    glfwDestroyWindow(window);
    glfwTerminate();
}

5. 호출·오류·수명 주의점

  • GL/glew.h를 gl.h보다 먼저 포함한다. GLFW_INCLUDE_NONE은 GLFW의 GL 헤더 자동 포함을 막는다.
  • 현재 프레임워크의 gl.GenBuffers 호출을 GLEW 매크로 glGenBuffers로 임의 교체하지 않는다. 함수 주소 저장 위치와 초기화 경로가 다르다.
  • GLEW 초기화 성공, 컨텍스트의 기능 지원, OpenGL 명령의 오류 여부를 별도로 판단한다.
  • 컨텍스트나 실행 스레드를 바꿀 때 기존 함수 주소와 자원 사용 조건이 그대로 유지된다고 가정하지 않는다.

참고 자료와 확인 범위

동봉 GL/glew.h · Native.h: GlfwApi / GlApi / Module · Renderer.cpp: initialize · Application.cpp: ensureContext / shutdown

GLEW 공식 사용 안내. 함수 선언·반환 타입은 동봉 헤더를 기준으로 적었다. 동봉 폴더 이름은 바이너리 실행 버전을 검증한 결과가 아니다.

프로젝트에서 사용하는 API와 핵심 학습 API를 정리한 문서이다. 라이브러리 전체 API를 전부 나열하지 않는다. 아래 예제는 설명용이며 프로젝트 파일에 적용하지 않았다. 빌드·테스트·브라우저·인쇄 확인은 실행하지 않았다.
