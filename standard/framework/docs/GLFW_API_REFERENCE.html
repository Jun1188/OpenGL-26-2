GLFW API 명세

창·컨텍스트·입력·프레임 루프의 계약을 현재 GlfwApi의 25개 함수와 연결한다.

기존 API 문서GLEWGLFWGLM

작성 기준: 2026-11-03 · 동봉 GLFW 3.4 헤더 및 glfw-3.4.bin.WIN64 · UTF-8 BOM · 정적 소스와 공식 문서 기준

역할·소유권호출 순서함수 인덱스콜백 인자루프 예제근거

1. 역할과 프로젝트 연결

GLFW는 창·컨텍스트·입력·시간을 제공한다. Renderer의 도형이나 GLM 행렬을 소유하지 않는다. 현재 구현은 glfw3.dll의 심볼을 GlfwApi의 함수 포인터로 저장한다. 예를 들어 detail::glfw().Init()은 glfwInit에 대응한다. 아래 선언은 GLFW 공개 API이며 DLL 장식 매크로는 생략했다.

소유 주체대상수명 계약
ApplicationGLFWwindow* / GLFW 초기화 상태initialize에서 생성하고 shutdown에서 해제한다.
GLFW네이티브 창·컨텍스트glfwDestroyWindow 또는 glfwTerminate로 제거한다.
창 user pointerApplication* 비소유 포인터glfwSetWindowUserPointer는 객체를 복사·해제하지 않는다. 콜백 실행 중 포인터가 유효해야 한다.
Module / GlfwApiDLL 핸들·함수 주소Native.h의 load가 주소를 저장한다. DLL 주소를 얻는 단계와 GLFW 초기화는 별개이다.

2. 실제 호출 순서

DLL 로딩 → 오류 콜백 등록 → Init → WindowHint → createWindow → MakeContextCurrent → Renderer 초기화 → 입력 콜백 등록
PollEvents → 입력 콜백 → 종료 확인 → 프레임버퍼 크기 확인 → GetTime → dt → 사용자 갱신 → 모션 → 렌더링 → SwapBuffers → 반복

프레임버퍼 크기가 0이면 현재 구현은 WaitEvents 후 시간을 재설정하고 다음 반복으로 간다. dt는 0~0.05초로 제한한다. 종료 시 정상 컨텍스트에서는 renderer.destroy(), 컨텍스트 연결 실패 시 renderer.abandon()을 호출한 뒤 창과 GLFW를 정리한다.

4. 콜백과 좌표 계약

콜백 등록은 주소 저장이다. 이벤트가 발생했을 때 GLFW가 등록 함수를 호출한다. 현재 구현은 PollEvents에서 입력을 처리하지만, 창 관련 GLFW 함수가 콜백을 동기적으로 유발할 수도 있으므로 모든 콜백이 PollEvents 안에서만 실행된다고 가정하지 않는다.

// GLFW → 등록한 람다 → Application::dispatch → 사용자 핸들러
// key: 논리 키, scancode: 플랫폼 스캔 코드, action: PRESS/RELEASE/REPEAT
// mods: SHIFT/CONTROL/ALT 등의 비트 조합

현재 Application은 dispatch 경유 콜백 예외를 저장하고 이벤트 처리 후 다시 던진다. C 콜백 경계를 넘어 C++ 예외를 직접 전파하는 예제로 해석하지 않는다.

5. 프레임 루프와 종료 예제

GLFW 초기화·창 생성·함수 로딩이 성공한 뒤의 설명용 조각이다. 실제 앱은 ensureContext와 Diagnostics도 수행한다.

double previous = glfwGetTime();
while (!glfwWindowShouldClose(window)) {
    glfwPollEvents();
    if (glfwWindowShouldClose(window)) break;
    int width = 0, height = 0;
    glfwGetFramebufferSize(window, &width, &height);
    if (width <= 0 || height <= 0) {
        glfwWaitEvents();
        previous = glfwGetTime();
        continue;
    }
    const double now = glfwGetTime();
    const float dt = static_cast<float>(std::clamp(now - previous, 0.0, 0.05));
    previous = now;
    // 유효한 current 컨텍스트에서 dt로 갱신하고 렌더링한다.
    glfwSwapBuffers(window);
}
// GL 자원 정리 → user pointer 해제 → 창 제거 → GLFW 종료
// std::clamp는 <algorithm>과 C++17 이상이 필요하다.

참고 자료와 확인 범위

동봉 GLFW/glfw3.h · Native.h: GlfwApi / GlApi / Module · Application.cpp

공식 보충 자료: 초기화·스레드 · 창·이벤트 · 컨텍스트 · 입력·시간. 상세 선언과 계약은 동봉 3.4 헤더의 해당 함수 주석을 기준으로 정리했다.

프로젝트에서 사용하는 API와 핵심 학습 API를 정리한 문서이다. 라이브러리 전체 API를 전부 나열하지 않는다. 아래 예제는 설명용이며 프로젝트 파일에 적용하지 않았다. 빌드·테스트·브라우저·인쇄 확인은 실행하지 않았다.
