# standard 사용자 확인 절차

아래 빌드·실행·배포 확인은 사용자가 수행한다. 에이전트는 빌드, 테스트, 검증기, 실행 파일 생성, 창 표시, 입력 재현을 수행하지 않았다. 파일·본문·인코딩·설정·해시의 읽기 전용 대조와 AST 구조 생성만 수행했다.

## 1. 프로젝트와 출력

1. standard.slnx를 열고 standard를 시작 프로젝트로 선택한다.
2. C++17, v145, Windows SDK 10.0이 준비되어 있는지 확인한다. Debug/Release의 x64 구성을 각각 빌드한다.
3. 출력 폴더에 standard.exe와 framework/dependencies/.../glfw3.dll이 있는지 확인한다. 상대경로 구조와 라이선스가 유지되어야 한다.
4. F5 실행으로 콘솔과 렌더링 창을 확인한다. 한글 도움말에 깨진 문자가 없어야 한다. 외부 모델·텍스처가 없어도 기본 장면이 나타나야 한다.
5. 컴파일할 main은 standard/main.cpp 하나다. framework/examples의 main 파일을 추가하면 중복 진입점이 된다.

## 2. 조작과 예상 결과

| 순서 | 입력 | 확인할 결과 |
|---|---|---|
| 1 | 초기 실행 | 두 직육면체와 부착 기저가 같은 시간으로 타원 이동·자전. 파랑 객체는 YZ평면 반사 |
| 2 | Space 두 번 | 첫 입력은 현재 자세를 유지. 두 번째 입력은 같은 위상에서 재개 |
| 3 | S 두 번 | 자전만 사라졌다가 현재 시각의 자전으로 복귀. 경로는 계속 이동 |
| 4 | 1~6 | 안내된 경로로 전환하며 경로의 시각만 0으로 변경. 6번은 끝에서 점프하지 않고 왕복 |
| 5 | 4 후 M 반복 | z가 있는 사용자 경로에서 평면·점·직선 대칭의 차이 관찰. 반사 없음에서는 두 객체가 겹침 |
| 6 | G 두 번 | 루트 공전이 객체·부착 기저·소유자 없는 회색 선에 모두 적용되었다가 제거 |
| 7 | I 두 번 | 첫 객체와 부착 기저만 1.5배 확대 후 복귀. 경로·다른 객체·말단 바인딩 유지 |
| 8 | 움직이는 두 객체 클릭 | 화면의 객체 위치에서 entity/face ID 출력. 반사·공전 상태에서도 위치 일치 |
| 9 | H | 한글 조작 안내 재출력 |
| 10 | 창 크기 변경·최소화·복구·포커스 이탈 | 화면 비율과 클릭 위치 확인. 최소화 시간만큼 크게 점프하지 않고 재개. 지속 입력 상태 없음 |
| 11 | Esc와 창 닫기 | 종료와 자원 정리 확인 |

## 3. 단독 폴더 공유

1. standard 소스 폴더 전체를 ZIP으로 복사하되 .vs/x64/*.vcxproj.user는 제외한다. 내부 framework/dependencies와 라이선스는 포함한다.
2. 원래 저장소 밖의 경로로 압축을 푼다. 부모 폴더에 다른 실습·공용 framework가 없는 조건에서 standard.slnx를 빌드한다.
3. 해당 PC에 맞는 도구 집합·SDK·드라이버 조건을 확인하고 Debug/Release x64에서 빌드·F5를 실행한다. 라이브러리 경로에 원래 PC의 사용자 경로가 요구되지 않아야 한다.
4. Release 출력 폴더의 standard.exe와 옆 framework를 별도 폴더에 복사한다. 그 EXE를 실행하고, 다른 작업 폴더에서 실행해도 DLL과 초기 장면을 찾는지 확인한다.
5. 경로의 정적 대조와 실제 다른 PC 실행을 구분해서 결과를 기록한다. 오류가 나면 구성, 도구 집합, 오류 전문, 실제 EXE·DLL 위치를 함께 확인한다.

## 4. 변경 경계

이 샘플을 만든 작업은 실습 1~19와 루트 프레임워크의 기존 파일을 변경하지 않았다. 향후 공용 프레임워크 수정은 루트에 먼저 반영하고, standard에 필요한 버전을 명시적으로 배포한다. tools/Sync-Framework.ps1은 실습 사본을 덮어쓰므로 이 샘플 생성에는 사용하지 않았다.
