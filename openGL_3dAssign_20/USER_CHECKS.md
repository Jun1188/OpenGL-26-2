# 사용자 확인: 실습 20

아래 절차는 사용자 실행용이다. 에이전트는 빌드·실행·테스트·검증기를 실행하지 않았다. 관찰 결과와 오류 메시지를 별도로 기록한다.

## 1. Debug / Release x64

1. `openGL_assign_20.sln`을 Visual Studio에서 연다. Debug x64를 선택해 빌드하고 실행한다.
2. Release x64에서도 빌드하고 실행한다. `.slnx`를 지원하는 Visual Studio에서는 같은 프로젝트가 열리는지 확인한다.
3. 예상: 바닥, y=1의 ㄱ자 벨트, 줄무늬 30개, 색이 다른 상자5개가 보인다. 상자는 정지 상태에서 시작한다. 숫자 1~5가 읽혀야 한다. 콘솔에 키 안내가 표시되어야 한다.
4. 오류가 있으면 콘솔의 단계·API·원인과 종료 코드를 기록한다. 초기화나 장면 생성 실패가 정상 종료 코드로 숨겨지면 안 된다.

## 2. 이동과 거리

1. b를 누른다. 벨트 줄무늬와 상자가 같은 속도로 이동하는지 본다. 1초 이동의 경로거리는 1.25이며 한 순환의 시뮬레이션 시간은 9.6초다. 실행 프레임의 dt 제한과 최소화 대기 때문에 실제 벽시계 시간과 차이가 날 수 있다.
2. 상자1을 따라간다. +X 구간에서 +Z 구간으로 넘어갈 때 상자와 번호가 함께 90도 회전해야 한다. 코너에서 상자 크기가 달라지면 안 된다.
3. 끝에 도달한 상자와 줄무늬는 시작 위치로 순간 이동해야 한다. 대각선 복귀나 외부 복귀 경로가 보이면 안 된다.
4. 5개 상자의 경로상 간격은 2.4다. 코너 양쪽 상자의 직선거리는 이보다 짧아지는 것이 정상이다. 순환 번호가 경로상 순서를 유지해야 한다.
5. b를 다시 누른다. 상자와 줄무늬가 동시에 정지하고 서로 미끄러지지 않아야 한다. b 재시작 시 현재 위치에서 이어져야 한다. b를 길게 눌러도 반복 이벤트 때문에 여러 번 토글되면 안 된다.

## 3. 카메라와 수정키

1. +와 - 및 숫자패드 +/−를 누른다. 원근에서는 거리, 직각에서는 표시 범위가 바뀐다. 줌 범위 끝에서 계속 눌러도 오류 종료나 무효 행렬이 생기면 안 된다.
2. Caps Lock을 끈 상태에서 p: 원근, Shift+p: 직각. Caps Lock을 켠 상태에서 p: 직각, Shift+p: 원근을 확인한다.
3. ←를 누르면 위에서 본 시계방향, →는 반시계방향으로 주목점 주위를 돌아야 한다. 두 키를 함께 누르면 회전하지 않아야 한다. 키를 놓으면 멈춰야 한다. 고도·주목점은 유지되어야 한다.
4. 정지 상태에서도 카메라 조작이 가능해야 한다. 상자를 여러 방향에서 볼 때 번호가 옆면 밖에 표시되고 벨트·바닥과 겹쳐 깜빡이지 않아야 한다.
5. 화살표를 누른 채 Alt+Tab으로 포커스를 옮기고 키를 놓는다. 창에 돌아와도 공전이 계속되면 안 된다.

## 4. 리셋과 종료

1. 이동 중 줌·공전·직각 투영을 변경하고 r을 누른다.
2. 예상: 시간0·정지·처음 배치·원근·초기 카메라·초기 직각 범위·누름 상태가 모두 복원된다. r을 반복해도 객체나 번호가 늘어나면 안 된다.
3. b를 누르면 최초 시작과 같은 배치에서 재시작해야 한다. q로 종료하고, 별도 실행에서는 창 닫기로 종료한다. 정상 종료 시 오류 메시지가 없어야 한다.

## 5. 창과 다른 PC

1. 가로·세로로 리사이즈한다. 장면의 종횡비가 자연스럽게 유지되어야 한다. 작은 창에서는 일부 장면이 잘릴 수 있으나 오류 종료가 없어야 한다.
2. 최소화 후 복원한다. 복원 시 큰 시간 점프로 한꺼번에 이동하거나 카메라가 무한 회전하면 안 된다.
3. DPI 배율이 다른 모니터로 창을 옮긴다. 렌더링이 창의 framebuffer 크기를 따라야 한다. 이 실습에는 피킹이 없다.
4. 프로젝트 폴더 전체를 다른 경로·다른 PC로 복사하고 설치된 Visual Studio C++ 도구로 Debug/Release x64를 빌드한다. 로컬 절대경로나 고정 v145 요구가 없어야 한다.
5. 출력 폴더의 실행 파일과 `framework` 하위 런타임을 함께 다른 경로로 복사해 실행한다. DLL 누락 시 오류의 경로·원인·조치가 표시되어야 한다. 원본 DLL은 삭제하지 말고 배포 복사본으로만 누락 상황을 확인한다.
