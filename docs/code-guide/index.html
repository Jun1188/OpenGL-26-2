공통 프레임워크와 실습 20~23의 각 HTML 앞부분에 심화 설명을 추가했다. 3개 부분 + α 구성을 유지한다. standard는 이번 보강 대상에 포함하지 않는다.

대상·함수입력 → 출력책임·경계
1. 렌더링·호출 흐름등록 → 이벤트 → 상태 → draw → 화면CPU와 GPU, 기본 렌더와 사용자 렌더를 구분
2. 추상화·소유 구조소유자 → 참조·ID → 변환 부모수명·초기화·리셋 시 유효성
3. 객체·함수 설명인자 → 결과 → 변경 상태 → 실패핵심 계약 표와 현재 실습 원본을 먼저 읽음
＋α 계산·명암·주의점수치 예제 → 실습별 차이 → 회상 질문직접 실행·브라우저 확인은 사용자 수행

중간고사 혼합·변형 문제를 읽고 무엇부터 구현할지 결정하는 자료다. 공통 행동과 API 호출을 먼저 배우고 실습은 적용 예시로 읽는다. 시험 규정·시간 제한·standard 사용 허용 여부는 실제 안내를 확인한다.

1. 시험 문제에서 구현 행동으로

요구사항 카드→행동 분기 선택→API 호출 순서→정적 장면→입력/갱신/표시→요구사항 대조

공통 행동 그래프 열기 — 요구사항 분해, 기능별 우선순위, 혼합 문제와 증상별 복귀 지점.

2. 행동을 코드로 연결

요구사항별 API 호출 순서 — 호출 골격·좌표 계약·실습 예시. 공개 API 전체 한글 검색 · API_KO.md. 모든 공개 함수 선언 바로 위에도 한글 기능 주석이 있다.

3. 실습별 적용 예시와 구조 참고

아래는 공통 행동을 실제 코드에 적용한 예시다. 각 대상의 호출/렌더 흐름, 추상화/소유 구조, 객체/함수, 계산/명암을 나눴다. SDK와 framework 배포 사본은 중복 분석하지 않는다.

그림자·명암

각 notes 페이지에서 방향광 명암/깊이 가림/Front culling/투영 그림자를 구분한다. 현재 셰이더에는 cast shadow 기법이 없다.

근거와 한계

code-only graphify AST + source-definition anchors, 외부 LLM/API 호출 0. 기존 query CLI는 UTF-8 BOM 입력을 읽지 못해 직접 UTF-8-SIG JSON 로딩으로 근거를 읽었다. 새 6개 scope 그래프를 각각 생성했다. 이번 보강에서 그래프를 재생성하지 않았다. 노드·간선 수와 소스 해시는 기존 생성 시점 기준이다. 생성 그래프의 dangling endpoint 및 동일 노드쌍 간선 축약은 GRAPH_HEALTH.md에 남아 있으므로 완전한 동적 호출 그래프로 해석하지 않는다.
