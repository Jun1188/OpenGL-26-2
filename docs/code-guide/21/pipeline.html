실습 21 · 회전 공간 · 1. 렌더링·호출 흐름

대상: 실습 21 · 회전 공간. 공통 프레임워크는 정규 원본을 분석하고 프로젝트 안의 SDK·프레임워크 중복 사본은 그래프에서 제외했다. 파이프라인은 GPU 흐름, 콜백은 CPU 실행 시점이다.

이 대상의 입력 → 상태 → 출력

키/마우스 dx→Yspin × Ztilt 방 자세→로컬 RoomBody→e: 모든 물체 release→월드 중력 적분→syncScene → 표시

v → 30도/초 Y자전 토글 → 방은 Front cull 유지. e → 바닥 face5 숨김 → 배열의 모든 미이탈 공·상자 release → 다음 update에서 모두 월드 중력 낙하. 바닥을 닫아도 이미 이탈한 물체는 계속 떨어진다.

이 프로젝트의 main → initScene → onUpdate

공통 실행 순서: 등록과 실행을 분리

main: 객체 생성→set...Handler: 람다 저장→run: 창/컨텍스트/셰이더→initHandler: Scene 생성→PollEvents → 입력 콜백→update → 자동 Motion → render → swap

main의 set...Handler 호출은 함수를 등록한다. 람다 본문은 run이 나중에 실행한다. initHandler는 초기화 뒤 한 번, updateHandler는 프레임마다, renderHandler가 없으면 renderScene이 실행된다. dt는 [0,.05]로 제한하고 최소화에서는 이벤트 대기로 진행을 멈춘다.

이 대상의 계산 예시

공은 중심 허용 범위 [min+radius,max-radius]에서 반사한다. 상자의 로컬 중력은 Rᵀg다. 미이탈 물체의 월드 위치는 R*p_local. e를 누르면 p_world=R*p_local, v_world=R*v_local로 옮긴 뒤 released=true. 이후 v+=g*dt, p+=v*dt.

컨텍스트·자원 정리

Application이 창/컨텍스트 수명을 가진다. ensureContext는 생성 스레드·GLFW current·실제 WGL context를 확인한다. 실패하면 GL 작업을 계속하지 않는다. 유효할 때 GPU destroy, 실패 상태에서는 abandon 후 창 파괴로 회수한다. 각 viewport는 별도 컨텍스트가 아니다.

Application::ensureContext
소스와 graphify AST/정의 앵커를 대조한 학습 자료다. 실행 순서 설명은 실제 콜백 코드로 보완했다. 그래프의 동명 심볼·함수 포인터 간선은 확정 호출로 해석하지 않는다. 빌드·실행·테스트·검증기·브라우저 시각 확인은 수행하지 않았고 사용자에게 맡긴다. ZIP을 만들지 않았다.
