컨텍스트를 포함한 종료 순서

shutdown은 assets_를 reset한 뒤 컨텍스트가 유효하면 Renderer::destroy를 호출한다. 실패 상태면 abandon으로 CPU 측 핸들·캐시를 비우는 경로를 택한다. 이후 창 user pointer 제거 → DestroyWindow → GLFW Terminate 순서다. Scene 데이터 소멸과 GL 리소스 삭제는 서로 다른 작업이다.

이 대상의 응용 상태

Application은 Scene/Camera/Renderer/옵션을 소유한다. Scene은 CPU 컴포넌트와 ID 관계, Renderer는 GPU 핸들·텍스처 캐시, Module은 DLL 핸들을 소유한다.

Application
  ├ Scene → Component_Poly/Model/Face + Line3D + MotionSystem
  ├ Camera + RenderOptions
  ├ Renderer → VAO/VBO/EBO/program + texture cache
  ├ optional AssetLoader → weak image cache
  └ callback std::function → 외부 Console 참조
Module → HMODULE / GLFWwindow* → 네이티브 창 핸들

합성에서 흔한 소유·상태 오류

표시 객체를 방의 자식으로 둔 뒤 물리에서 계산한 월드 위치를 다시 넣으면 회전/이동이 중복될 수 있다. Motion이 움직이는 위치를 Console에서 또 덮어쓰지 않는다. 물리 상태 → 최종 위치를 결정하는 책임을 한곳에 둔다. 새 프레임마다 모델을 재생성하는 것과 transform만 갱신하는 것은 비용과 수명이 다르다.

GL 함수 포인터·콜백은 정적 그래프가 실행 순서를 완전히 복원하지 못한다. __FILE__은 /utf-8에서 u8path로 변환한다. WGL current 확인 실패 후 GL 명령이나 삭제를 계속 호출하지 않는다.

이번 보강은 실제 소스 읽기를 기준으로 했다. 기존 graphify와 소스 스냅샷은 재생성하지 않았다. 실행 순서 설명은 실제 콜백 코드로 보완했다. 그래프의 동명 심볼·함수 포인터 간선은 확정 호출로 해석하지 않는다. 빌드·실행·테스트·검증기·브라우저 시각 확인은 수행하지 않았고 사용자에게 맡긴다. ZIP을 만들지 않았다.
