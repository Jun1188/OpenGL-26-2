업로드와 프레임별 변환

renderPass는 Scene 주소·geometry revision·textures 옵션이 직전 값과 다르면 upload한다. upload는 메시를 GpuVertex와 인덱스·DrawRange로 모아 BufferData로 보낸다. draw는 현재 Scene의 행렬·가시성·tint를 읽는다. 위치 변경과 정점 배열 재업로드를 같은 작업으로 취급하지 않는다.

upload는 임시 텍스처 맵을 만들고 실패 시 정리한다. 성공하면 기존 캐시를 교체한다. renderViews는 전체 framebuffer를 지운 후 각 pass를 순서대로 실행한다. renderPass는 viewport와 scissor를 설정하고 해당 영역의 가로/세로 비율로 projection을 계산한다.

원본과 확인 범위

2026-11-01 실제 소스를 읽어 보강했다. 링크는 원본 파일을 연다. 기존 sources.html·graphify는 재생성하지 않았으므로 최신 코드와 차이가 있을 수 있다. 빌드·실행·테스트·검증기·브라우저 확인은 사용자에게 맡긴다.

framework/detail/Application.inl · framework/detail/Renderer.inl · framework/detail/Scene.inl · framework/detail/Shaders.h

대상: 공통 프레임워크. 공통 프레임워크는 정규 원본을 분석하고 프로젝트 안의 SDK·프레임워크 중복 사본은 그래프에서 제외했다. 파이프라인은 GPU 흐름, 콜백은 CPU 실행 시점이다.

이 대상의 입력 → 상태 → 출력

Application: 입력·수명→Scene/Motion: CPU 상태→Renderer.upload: VBO/EBO/VAO→Vertex shader: MVP→클리핑·래스터화→Fragment shader·depth·swap

main에서 등록한 init 람다는 run 초기화 뒤 실행한다. 매 루프 PollEvents → updateHandler → Scene.updateMotions → renderHandler 또는 renderScene → SwapBuffers. 최소화 시 WaitEvents와 시간 기준 갱신, 종료 시 GPU→window→GLFW 순서다.

공통 실행 순서: 등록과 실행을 분리

main: 객체 생성→set...Handler: 람다 저장→run: 창/컨텍스트/셰이더→initHandler: Scene 생성→PollEvents → 입력 콜백→update → 자동 Motion → render → swap

main의 set...Handler 호출은 함수를 등록한다. 람다 본문은 run이 나중에 실행한다. initHandler는 초기화 뒤 한 번, updateHandler는 프레임마다, renderHandler가 없으면 renderScene이 실행된다. dt는 [0,.05]로 제한하고 최소화에서는 이벤트 대기로 진행을 멈춘다.

이 대상의 계산 예시

local=T(basis)*R*S*T(-localBasis), world=부모 행렬과 레이어 합성, clip=P*V*M*p. 법선은 비균일 배율에서 mat3(M)의 역전치로 변환한다. 렌더러는 geometry revision이 변할 때만 정점 배열을 다시 업로드한다.

컨텍스트·자원 정리

Application이 창/컨텍스트 수명을 가진다. ensureContext는 생성 스레드·GLFW current·실제 WGL context를 확인한다. 실패하면 GL 작업을 계속하지 않는다. 유효할 때 GPU destroy, 실패 상태에서는 abandon 후 창 파괴로 회수한다. 각 viewport는 별도 컨텍스트가 아니다.
