계산을 코드와 연결

각 pass마다 MVP=P_i*V_i*M. 원근은 왼쪽 2/3, XZ 평면도는 오른쪽 위, XY 정면도는 오른쪽 아래. aspect=각 viewport.width/height. scissor가 clear 범위를 제한하고 깊이 버퍼 간섭을 막는다.

오른쪽 방향키 → position.x += speed*dt 한 번 → root 이동 → 원근/평면도/정면도가 같은 M을 각각 다른 P,V로 읽는다. renderViews 안에서 onUpdate를 다시 호출하지 않는다.

그림자처럼 보이는 부분의 실제 계산

실습 22은 Console 초기화에서 lighting=true를 켠다.

현재 기본 GLSL에는 shadow map·light-space depth 비교·투영 그림자 계산이 없다. 광원 방향과 표면 법선으로 표면 명암(shading)을 계산한다. 물체가 다른 표면에 드리우는 투영 그림자(cast shadow)와 다르다.

처리이 코드의 동작구분 기준
방향광 명암lighting=true인 삼각형 면에서 N·L을 사용한다.빛을 등진 면 자체가 어두워진다. 바닥의 다른 위치에 그림자를 만들지 않는다.
은면 제거depthTest, GL_LESS와 깊이 버퍼로 가까운 조각을 남긴다.관찰 카메라 기준 가림이다. 광원 기준 가시성 검사는 아니다.
Front cull방 메시를 사용하는 경우 바깥 winding의 앞면을 버려 내부를 보이게 한다. 방이 없는 실습의 기본 동작으로 해석하지 않는다.삼각형 winding을 이용한 면 제거다. 조명·그림자와 별개다.
와이어프레임 depth prepass선 뒤의 면을 깊이에 먼저 기록해 뒷선을 가린다.빛이 만든 그림자 패스가 아니다.
실제 그림자현재 구현 없음.추가하려면 광원 관점 깊이 맵/비교, bias·자원·추가 pass 설계가 필요하다. 이번 작업에 구현하지 않았다.
N = normalize(uNormalMatrix * localNormal)
L = normalize(uLightDirection)
brightness = 0.25 + 0.75 * max(dot(N,L), 0)
color.rgb *= brightness * uLightColor
N·L=1 → 1.0, N·L=0 → 0.25, N·L=-1 → 0.25

0.25는 고정 주변광처럼 더한 밝기다. 물리 기반 간접광 계산은 아니다. 면 안쪽을 그리는 방은 vertex normal을 반대로 만들어 조명 방향도 내부 표면에 맞춘다. 선은 조명 적용을 끈다. 텍스처는 옵션을 켠 경우 색에 곱한다.

실제 fragment shader · draw 상태/법선 uniform
실제 내장 셰이더 전체
#pragma once
namespace graphics::detail {
inline constexpr char vertexShader[] = R"GLSL(#version 330 core
layout(location=0) in vec3 vPos;
layout(location=1) in vec3 vColor;
layout(location=2) in vec2 vTexCoord;
layout(location=3) in vec3 vNormal;
uniform mat4 uMVP;
uniform mat4 uModel;
uniform mat3 uNormalMatrix;
out vec3 outColor;
out vec2 TexCoord;
out vec3 Normal;
void main() {
    gl_Position = uMVP * vec4(vPos, 1.0);
    outColor = vColor;
    TexCoord = vTexCoord;
    Normal = uNormalMatrix * vNormal;
}
)GLSL";
inline constexpr char fragmentShader[] = R"GLSL(#version 330 core
in vec3 outColor;
in vec2 TexCoord;
in vec3 Normal;
uniform sampler2D uTexture;
uniform bool uHasTexture;
uniform bool uLighting;
uniform vec3 uLightDirection;
uniform vec3 uLightColor;
uniform bool uOverrideColor;
uniform vec3 uOutlineColor;
uniform vec3 uTint;
out vec4 FragColor;
void main() {
    if (uOverrideColor) { FragColor = vec4(uOutlineColor, 1.0); return; }
    vec4 color = vec4(outColor * uTint, 1.0);
    if (uHasTexture) color *= texture(uTexture, TexCoord);
    if (uLighting && length(Normal) > 0.0)
        color.rgb *= (0.25 + 0.75 * max(dot(normalize(Normal), normalize(uLightDirection)), 0.0)) * uLightColor;
    FragColor = color;
}
)GLSL";
}

실패 증상 → 먼저 볼 위치

증상점검 순서
콘솔만 뜨고 종료첫 ERROR의 stage/Source/Operation → UTF-8 경로·DLL → 컨텍스트 → 셰이더 순서. 예외 catch 줄을 실제 결함 줄과 혼동하지 않는다.
객체가 안 보임정점/인덱스 → 모델/부모 변환 → 카메라/클립 → winding/culling → depth → shader/tint 순서로 좁힌다.
리셋 후 다른 객체가 움직임Scene::clear 이후 ID 재발급, 캐시된 ID/포인터·입력 상태가 남았는지 확인한다.
시간·속도가 두 배onUpdate와 Scene.updateMotions의 중복 갱신 여부, pass마다 시간 갱신 여부를 확인한다.
어두운 면이 그림자처럼 보임uLighting·N·L과 normal matrix를 먼저 읽는다. 현재 그림자 맵이 있다고 추정하지 않는다.

사용자에게 맡기는 최소 확인

glViewport만 바꾸면 glClear가 영역 밖까지 지울 수 있다. 3뷰에 WGL 컨텍스트 세 개를 만들 필요가 없다. 포신은 몸체 중심, 깃대는 밑점 피벗을 유지한다.

해당 .sln의 Debug/Release x64 빌드·실행, 모든 키·리셋·포커스·최소화·리사이즈·DPI를 확인한다. 에이전트는 수행하지 않았다. HTML 검색/탐색과 그래프 렌더도 브라우저에서 직접 확인해야 한다.

이번 보강은 실제 소스 읽기를 기준으로 했다. 기존 graphify와 소스 스냅샷은 재생성하지 않았다. 실행 순서 설명은 실제 콜백 코드로 보완했다. 그래프의 동명 심볼·함수 포인터 간선은 확정 호출로 해석하지 않는다. 빌드·실행·테스트·검증기·브라우저 시각 확인은 수행하지 않았고 사용자에게 맡긴다. ZIP을 만들지 않았다.
