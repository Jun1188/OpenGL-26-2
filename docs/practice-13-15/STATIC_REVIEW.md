# 최종 정적 확인

- 네 framework 사본의 전체 457개 파일은 바이트가 동일하다. 필수 라이브러리·DLL·라이선스를 포함한다.
- 각 실습의 프로젝트 XML 소스·헤더·리소스·셰이더 참조 파일은 존재한다.
- 실습 13·14·15의 프로젝트 GUID는 서로 다르고 각 솔루션과 일치한다.
- 자체 코드·프로젝트·리소스·셰이더·문서에는 UTF-8 BOM을 사용한다.
- 외부 의존성은 기존 바이트를 유지했다. 전달하는 그래프 JSON도 UTF-8 BOM이다.
  JSON을 Python에서 읽을 때 encoding="utf-8-sig"를 사용한다.
- 변경 대조 문서에는 모든 자체 코드의 전체 before/after와 동일 사본 적용 경로를 기록했다.
  원본 코드와 외부 파일의 기존 공백은 대조 자료와 사본에서 보존한다.
- C++ 구현 파일은 정적 문법 파서로 읽었다. 헤더의 {} 기본 인수는 해당 파서에서 missing node가
  생성되므로 문법 판정에 한계가 있다. 컴파일·타입 검증 성공으로 해석하지 않는다.
- graphify는 코드 107개를 추출했다. 추출 실패 파일 0. 미해결 끝점 270, 동일 끝점 병합 93,
  자기 참조 3. 서로 다른 실행 프로젝트의 기호 관계 16개는 AMBIGUOUS이다.
- 외부 API를 호출하지 않았다. graphify의 외부 API 토큰 사용은 0이다.
- 빌드, 실행, UI, 종료 동작 테스트와 benchmark는 실행하지 않았다. 사용자 확인 필요다.
- 기존 sample0 빌드 출력 변경, 실습 13 packages와 입력 PDF는 이번 커밋에 포함하지 않았다.

## 후속 소스 검토: 실습 15 중첩 모션

- 단일 motion_을 motions_ 배열로 교체했다. 모든 모션은 독립 상태와 진행량을 가진다.
- S는 왼쪽2·오른쪽3을 처리한다. 1/2는 시간 진행을 모듈러로 반복하고 재입력으로 정지·재개한다.
- 2는 90도 교체와 복귀를 왕복한다. F/B는 [0,1]에서 자기 모션만 완료한다.
- 여섯 단위행렬에서 T/F/S/B/1/2/4/5 순서로 합성한다. B의 숨김은 뒷면에만 적용한다.
- P는 면 상태를 초기화하고 R은 전체 상태를 초기화한다. 사각뿔은 객체 자전만 적용한다.
- 위 내용은 소스 검토다. 컴파일, 렌더링, 시간 경계, 입력 조합의 실행 검증은 사용자 확인 필요다.
- 최신 graphify-out/PRACTICE15.md 및 SOURCE_HASHES.json에서 동작과 분석 소스 시점을 확인한다.
