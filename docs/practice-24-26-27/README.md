# 실습 24·26·27과 공통 확장 결과

태그한 튜토리얼 작업의 완료 알림과 커밋 9d01320을 확인한 뒤 시작했다. 아래 완료는 최종 소스·문서의 저장과 커밋에 관한 것이다. 빌드·테스트·검증기·앱·브라우저·폴더 분리 실행은 하지 않았다.

## 구현

- 실습 24: 실습 20의 L자 벨트·상자와 기존 입력을 유지하고 트럭·적재·상자 시점·트럭 경계 상태를 추가했다. 사용자 추가 지시에 따라 트럭은 벨트 세로 구간 바깥 X=5.5, 초기 Z=1.0에 나란히 두고 바닥은 22×21로 유지했다. 상자 지역 카메라는 (0,0.775,-1.425)로 뒤로 물려 화면 아래 상자 일부가 보이도록 조정했다. 상자별 카메라 후보 5개를 적재 전후 동일 EntityId의 최종 월드 행렬에서 갱신한다. V/n/N에서 후보 좌표와 선택 번호를 표시한다.
- 실습 26: 육면체/사각뿔, 조명 토글, 자체 Y 회전, 광원 양방향 Y 공전, 원 궤도, 거리와 궤도 반지름의 연동을 작성했다. 거리 증가 시 전체 궤도를 볼 수 있게 관찰 거리를 조정한다.
- 실습 27: 위치·크기·재질색이 다른 구 3개, 앞쪽 점광원과 작은 비조명 표시, 세 광원색 순환, 양방향 공전을 작성했다.
- 공통 API: Phong 재질 계수, 독립 주변광, 카메라 위치·재질 uniform, 비조명 재질, 부착 카메라 변환을 추가했다. 기본 계수에서는 이전 조명 계산을 유지한다. 루트/Standard/24/26/27에 필요한 동일 구현을 포함했다.
- Standard: 새 실습 모드는 추가하지 않았다. 재질 명령, 독립 주변광 저장, 부착·인계·반지름·재질 템플릿 4개를 추가했다. 새로운 사물의 규칙을 기존 사용자 콜백으로 연결하는 MovingBeacon C++ 참조를 추가했다.

## 폴더 독립성 교정

초기 신규 프로젝트가 ../framework를 직접 참조한 것은 잘못된 재사용 선택이었다. 사용자 지적 후 각 실습 폴더에 프레임워크 소스·헤더·라이브러리·DLL·셰이더·라이선스의 독립 사본을 넣고 로컬 프로젝트 참조로 바꿨다. 각 실습은 자기 폴더만 복사하는 배포 단위다. 시스템 컴파일러·Windows SDK·OpenGL 드라이버 요구는 별도다.

지역 스킬과 저장소 AGENTS.md에 이 경계를 명시했다. 개인 ponytail과 공유 기준본의 일반 재사용 규칙도 보완했다. 공유 스킬/로그 커밋 5597a28은 origin/main으로 일반 push했다. 다른 PC에 직접 적용하거나 원격 실행한 것은 아니다.

## 남은 사용자 확인

각 독립 폴더의 USER_CHECKS.md와 24의 CAMERA_MAPPING.md를 따른다. 특히 사용자 보고의 시점 문제가 실제 화면에서 해소됐는지는 실행 결과가 필요하다. 소스에서 후보 번호·실제 ID·월드 좌표 매핑을 검토한 결과와 실행 검증은 구분한다. 범용 사용자 콜백을 제공하지만 새로운 사물의 제약·힘 법칙까지 자동으로 만드는 기능은 아니다.

작업 중 추가된 `openGL_3dAssign_26/framework/detail/Renderer.cpp`의 사용자 공백/빈 줄 변경은 보존하고 최종 작업 커밋에서 제외했다. 사용자 PDF·docs.zip·기존 Python 캐시도 보존했다.
