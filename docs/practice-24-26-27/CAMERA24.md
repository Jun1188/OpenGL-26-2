# 실습 24 배치와 상자별 시점 대응

사용자 보고: v 전환 후 선택 상자의 일부가 화면 아래에 보이도록 카메라를 뒤로 물리고, 트럭을 PDF 그림처럼 L자 컨베이어의 바깥 옆에 나란히 배치해야 한다. 이전의 적재 전후 n/N 시점 매핑도 유지한다. 화면에서 보고된 정지 현상 자체를 재현하거나 특정 입력/카메라 오류로 확정하지 않았다. 다음은 최종 소스의 교정과 수식 검토다. 실제 실행은 사용자 확인 전이다.

## 배치

벨트는 기존 L자 두 구간을 유지한다. 가로 구간 X=-4.8~3.8, Z=-2.8~-1.2이며 세로 구간 X=2.2~3.8, Z=-1.2~3.8이다. 트럭의 초기 중심은 (5.5,0,1.0)이다. 세로 벨트의 바깥 모서리 X=3.8에 트럭이 나란히 서며, 바퀴를 포함한 최소 X는 5.5-1.225=4.275다. 벨트와의 간격은 0.475이며 서로 겹치지 않는다. 운전석은 -Z를 향한다. 트럭은 Z=-7.0~9.3에서 움직인다. 바닥은 X=-11~11, Z=-10~11, 즉 22×21이다. 운전석 앞 끝과 적재함 뒤 끝을 포함해 이 범위 안에 남도록 이동 경계를 정했다.

## 카메라의 ID·인덱스

`boxes_[i]`는 상자를 생성할 때 받은 실제 EntityId이고, `parcelViews_[i]`는 그 EntityId의 최종 worldMatrix에서 계산한 카메라다. 상자 번호는 i+1이며 `viewBox_`는 이 배열 인덱스다. 번호와 EntityId가 같다고 가정하지 않는다.

매 프레임 컨베이어/트럭 이동을 적용한 뒤 후보 5개 모두를 계산한다. 이동 중이거나 적재한 상자는 컨베이어 위치 갱신을 건너뛴다. 상자 이동은 컨베이어 시계와 독립된 dt로 진행하며, 이동 위치를 갱신한 뒤 카메라를 계산한다. 같은 worldMatrix 경로가 트럭 부모와 적재 부착을 포함하므로 적재 전후 다른 카메라 명단으로 교체하지 않는다.

`n`은 `(i+1)%5`, `N`은 `(i+4)%5`다. 1인칭에서만 동작한다. V 또는 n/N 입력 시 콘솔에 선택 번호, 실제 EntityId, 적재/벨트 상태, 후보 5개의 월드 좌표를 출력한다. `*`는 선택 후보다.

## 적재 전

상자 i의 경로 거리는 `clock.seconds*beltSpeed + conveyorLength*i/5`다. `conveyorCornerPose`의 위치·yaw에서 각 상자의 worldMatrix를 만들고 다음 지역 카메라를 변환한다.

```text
eyeLocal = (0, 0.775, -1.425)
targetLocal = eyeLocal + (0,0,1)
camera[i] = CameraSystem::attached(localCamera, worldMatrix(boxes[i]))
```

지역 Z를 0.505에서 -1.425로 옮겼다. 높이와 +Z 시선은 유지한다. 상자 윗면은 지역 Y=0.425이므로 카메라는 윗면보다 0.35 높고, 뒤쪽 면보다 1.0 뒤에 있다. 화면 아래에 선택한 상자의 윗부분이 들어오도록 한 배치이며, 실제 가림과 화면 내 크기는 사용자 실행 확인 전이다.

초기에는 상자 1·2·3이 가로 직선, 4가 코너, 5가 세로 직선에 있어 서로 다른 위치/방향을 가진다. 다섯 카메라 모두 현재 프레임의 실제 상자에서 계산된다. 예전 시점이 남은 후보를 선택하지 않는다.

## 모두 1초 이동을 마치고 적재한 직후, 트럭이 초기 위치에 정지한 경우

아래는 코드의 적재 슬롯과 카메라 오프셋으로 계산한 예상 좌표다. 실행 로그를 측정한 값이 아니다. 상자 높이는 Y=1.365, 카메라는 Y=2.140이며 방향은 적재 자세의 -Z다. 카메라는 상자보다 월드 +Z 쪽으로 1.425 뒤에 있다. 운전석 높이보다 시점을 높여 앞쪽 구조물이 시야 대부분을 가리는 상황을 줄였다.

| 상자 | 열/행 | 상자 월드 위치 | 예상 카메라 위치 |
|---|---|---|---|
| 1 | 왼쪽/앞 | (5.020,1.365,0.150) | (5.020,2.140,1.575) |
| 2 | 오른쪽/앞 | (5.980,1.365,0.150) | (5.980,2.140,1.575) |
| 3 | 왼쪽/중간 | (5.020,1.365,1.050) | (5.020,2.140,2.475) |
| 4 | 오른쪽/중간 | (5.980,1.365,1.050) | (5.980,2.140,2.475) |
| 5 | 왼쪽/뒤 | (5.020,1.365,1.950) | (5.020,2.140,3.375) |

슬롯 좌표는 적재 순서가 아닌 상자 인덱스에서 정한다. 5→1→2→3→4→5의 선택에서 Z 변화와 열의 X 변화가 각각 보여야 한다. 트럭이 움직이면 모든 좌표에 같은 truckZ 변화량을 더한다.

## 사용자가 확인할 순서

1. 리셋 후 트럭이 세로 벨트의 바깥 옆에 나란히 서 있는지 확인한다. V: 5번 별표와 세로 구간 시점인지, 화면 아래에 선택 상자의 일부가 보이는지 확인한다. n 다섯 번, N 다섯 번으로 번호/위치/방향을 확인한다.
2. 컨베이어를 b로 움직인 채 같은 순환을 확인한다. 후보 좌표가 프레임에 따라 달라져야 한다.
3. 상자 2와 5만 적재하고 순환한다. 두 후보는 트럭, 나머지는 벨트의 위치를 따라야 한다.
4. 전부 적재하고 위 표와 콘솔 좌표를 비교한다. 각 시점에서 선택 상자 윗부분이 아래쪽에 보이는지, 다른 상자나 운전석이 가리는지 확인한다. 서로 다른 행의 Z가 달라야 한다. g로 이동한 뒤에도 상대 간격이 유지돼야 한다.
5. V로 전체 시점에 복귀하면 이전 전체 시점이 돌아와야 한다. r 후에는 적재가 모두 해제되고 다시 5번부터 시작해야 한다.

이번 변경은 후보 매핑을 유지하면서 카메라를 뒤로 물리고 트럭을 벨트 세로 구간 바깥에 배치한 것이다. 사용자가 보고한 현상의 실제 해소 여부는 위 절차의 실행 결과로 확인해야 한다.

## 1~5 이동 중 확인

각 상자는 입력 시점 월드 위치와 자세를 저장한다. 1초 동안 위치만 glm::mix로 선형보간하며 기존 자세를 유지한다. 목표는 매 프레임 현재 트럭 슬롯이다. 트럭이 움직이면 고정된 두 월드 점 사이의 직선은 아니며 움직이는 목표로 수렴한다. 도착 시 최종 적재 자세(-Z 방향)를 적용하고 트럭에 부착한다. 위치 보간이며 회전 보간·충돌 회피는 포함하지 않는다.

1~5를 빠르게 입력해도 각 상자는 독립적으로 이동해야 한다. 같은 번호를 반복해도 이동이 재시작되지 않아야 한다. b 정지 중에도 적재 이동은 계속돼야 한다. 이동 도중 v/n/N은 상자 위치를 추적해야 하며 r은 이동을 취소하고 벨트 초기 상태를 복원해야 한다. 위 표의 예상 좌표는 적재 완료 후에만 적용한다.
